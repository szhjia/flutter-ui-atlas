# Flutter UI Atlas 架构与接入指南

[HTML 图文版](架构与接入指南.html)

普通 Flutter Web 应用可以直接通过浏览器采集，无需引入 SDK。开发者在本机安装 Atlas CLI。需要监听应用内部导航时，再在专用 Flutter 开发入口接入 Dart SDK。

| 部分 | 用途 | 接入方式 |
| --- | --- | --- |
| CLI 和浏览器采集器 | `atlas build` 采集页面，`atlas record` 按发现配置录制操作 | 和预编译的 Viewer 一起打包为 `flutter-ui-atlas`，安装在开发机。当前 `0.1.0` 从源码打包 |
| Viewer | 浏览截图和连线，也可在画布中打开真实页面 | 用 `atlas view` 启动，或在 React 工作台中本地引用 `@flutter-ui-atlas/viewer` |
| Dart SDK | 提供导航监听、场景准备和就绪判定接口 | 独立的 `flutter_ui_atlas` 本地包，按需加入应用的 `dev_dependencies` |

```text
已运行的 Flutter Web → Atlas 在 Chrome 中采集 → 截图和 manifest.json → Viewer 画布
```

采集器按配置访问路由、等待页面内容就绪并截图。验证连线时，它从来源页实际执行点击，确认目标路由匹配且目标内容已就绪，才将连线标记为 `observed`。只登记关系而未配置点击时，连线显示为 `declared`。

自己的 Flutter 工程可在根目录运行 `atlas init`。向导生成 `.atlas/atlas.yaml`、说明和忽略规则。启动配置中指定的 Flutter Web 后，运行 `atlas build` 和 `atlas view`，结果默认写入 `.atlas/generated/`。

## 跑一次「项目列表 → 项目详情」

1. 在 Atlas 仓库根目录打包并安装 CLI。开发机需准备 Node.js 22 或以上、pnpm 和 Google Chrome。

   ```sh
   pnpm install --frozen-lockfile
   pnpm run pack:cli
   npm install --global .runtime/packages/flutter-ui-atlas-0.1.0.tgz
   ```

2. 在 `examples/flutter_app` 目录构建并启动 Flutter Web。这个示例使用普通 `main.dart` 入口。

   ```sh
   flutter pub get
   flutter build web --debug --no-web-resources-cdn --target lib/main.dart
   python3 -m http.server 60210 --bind 127.0.0.1 --directory build/web
   ```

3. 保持 Flutter Web 服务运行。另开终端回到 Atlas 仓库根目录，采集并启动画布。

   ```sh
   atlas build --config examples/atlas.config.json
   atlas view --config examples/atlas.config.json --port 60322
   ```

4. 在 `atlas view` 终端出现启动地址后，用浏览器打开 `http://127.0.0.1:60322/`。`60210` 是 Flutter Web 的端口，`60322` 是此处指定的画布端口。画布打不开时，先确认 `atlas view` 仍在运行，再按终端打印的地址打开。画布能打开但实时预览打不开时，检查 Flutter Web 服务是否仍在运行，以及 `baseUrl` 是否指向该服务。

[示例配置](../examples/atlas.config.json) 已登记「项目列表」和「项目详情」，并指定点击「查看详情」来验证连线。接入自己的应用时，修改 `baseUrl`、路由模式、页面 `route`、就绪条件 `ready` 和连线操作 `click`。`build` 与 `view` 使用同一份配置。此示例的采集文件位于 `examples/.atlas/generated/`。更多字段见[协议与适配接口](协议与适配接口.md)。

## 按需注入导航监听

在应用的 `pubspec.yaml` 中，将 `flutter_ui_atlas` 加入 `dev_dependencies`，用 `path` 指向 Atlas 仓库里的 `packages/flutter_ui_atlas`。新增 `lib/main_atlas.dart`，把 observer 传给应用，应用再将它交给 `MaterialApp.navigatorObservers`。[示例依赖](../examples/flutter_app/pubspec.yaml) · [应用入口](../examples/flutter_app/lib/main.dart)

```dart
import 'package:flutter/widgets.dart';
import 'package:flutter_ui_atlas/flutter_ui_atlas.dart';
import 'main.dart';

void main() {
  WidgetsFlutterBinding.ensureInitialized().ensureSemantics();
  runApp(ExampleApp(observers: [
    AtlasNavigatorObserver((route) => debugPrint('ATLAS_LOCATION:$route')),
  ]));
}
```

调试时把 Flutter 命令的 `--target` 指向 `lib/main_atlas.dart`。示例 observer 把命名路由事件写到日志，CLI 的截图和连线验证仍由浏览器采集器负责。[SDK 入口源码](../examples/flutter_app/lib/main_atlas.dart)

上次演示用打包后的 CLI 在真实 Chrome 中采集了 4 个页面和 3 条已验证连线，并在画布内完成实时导航。单地址快捷模式 `--url` 未稳定通过，本文使用 JSON 配置流程。
