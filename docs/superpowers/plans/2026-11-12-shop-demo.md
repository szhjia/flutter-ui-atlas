# 普通 Demo 与通用采集实施计划

**目标：** Demo 回归普通 Flutter 工程；Atlas 通过配置页账户、声明式 YAML 与独立 Chrome 会话接入，无需专用 Flutter 入口。

**设计：** `docs/superpowers/specs/2026-11-12-shop-demo-design.md`。

**授权：** 按当前用户批准范围实施；不提交、推送、发布，不擅自修改 Git 索引或停止无关服务。旧专用入口方案的完成标记不适用于本计划。

## 工作顺序

1. 维护协议与适配接口，确定账户 UUID、页面模板 ID、私有快照、视口、步骤和实时会话契约。
2. 普通化 Demo：保留标准 `main.dart` 与独立 Flutter 配置、素材和测试；移除 SDK、专用入口、场景注入与生产 `scripts/shop-*`。保留独立测试 harness。
3. 根忽略规则：init 和配置服务维护 `/.atlas/`；原子更新、保留用户内容、拒绝链接和已跟踪文件，重复 init 不覆盖 YAML。
4. 快照与目录：配置页账户供构建读取，版本变化使旧快照失效；YAML 支持 profiles、screens.roles、prepare、ready.all、edges.steps；稳定身份跨批次复用。
5. 实时会话：工具管理独立 Chrome 登录、准备、就绪及资源清理；Viewer 与本机服务使用令牌和来源校验，旧 iframe 可选兼容。
6. 完成 CLI 接线，再验证完整标准路径、多账户两视口、失败保留好图和真实 Chrome 操作；分析一轮失败后批量修复，再复验相关回归。
7. 更新验证记录与交付说明，明确本轮、历史结果和未验证范围；独立审查后修复并复验。
