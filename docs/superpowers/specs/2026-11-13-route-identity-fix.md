# 同路由状态重复节点：根因与修复

## 复现与根因

用户在 `60218` 的 Sign in 分组看到默认登录与错误密码两个页面。原始真实 Demo 产物 `2026-11-13T00-09-46-964Z` 包含 16 个节点、21 条已验证操作，但仅有 11 个「账户、路由」组合。除了匿名 `/login`，两个账户的 `/products/cup` 与 `/cart` 也各有重复状态节点。

问题源头是模型契约：旧协议、接入技能与 Demo 目录把状态作为独立页面。YAML 的 9 个声明展开为 16 个账户页面，目录校验只检查页面 ID；采集器按声明截图，Viewer 按产物正常渲染，并非 React 重复渲染。自动发现也直接使用观察器的状态 ID，兼容合并旧图谱会延续重复。

Atlas 使用 YAML 或可信观察器提供的路由，不自动枚举 Flutter 内部路由表。标准浏览器采集同时校验实际入口、路由、账户和正文就绪；只截图不证明导航。

## 修复契约与边界

- 页面唯一性为稳定账户 UUID 与实际应用路由的组合。旧适配器无 UUID 时以 role 兼容。不同账户可以访问同一路由；显示名称、状态、入口查询参数不能创建同账户的新页面。
- 通用采集、YAML 展开、JSON 声明适配器统一拒绝重复路由和同节点导航。配置错误在启动 Chrome 或创建实时会话前失败。
- 自动发现将同账户同路由的状态 ID 归一至已有页面；原地变化不创建节点和导航。不同路由及真实身份切换仍可记录。旧的重复或无效产物不参与合并。
- Viewer 拒绝无效重复产物并要求重建，不静默隐藏卡片。
- 就绪判据支持 `any` 中的完整 `all` 内容分支，使同一购物车路由可验证空态或有数据正文。点击与填充目标仍限定为定位器，不能使用复合就绪表达式。
- Demo 只声明登录、首页、商城、产品详情、购物车、个人资料路由。错误密码、加入和移除商品继续由普通应用操作测试覆盖；这些操作不再被误记为导航。文档、协议、技能与测试契约同步修正。

## 证据与验收

新增 Node、组件与真实浏览器用例先复现失败：重复声明被接受、原地错误产生额外节点和假导航、Viewer 接受旧重复图谱。修复后覆盖重复拒绝、同名不同 UUID 账户隔离、严格操作定位器、真实导航、旧图谱重建、采集失败保留上一成功图及实时会话隔离。

真实 Flutter Demo 使用既有独立 Web 构建，经安装后的 CLI 完成 phone 与 pad 采集、实时操作及失败路径验收。实际成功批次 `2026-11-13T10-39-25-849Z` 有 11 个已采集页面、16 条真实操作验证的导航：匿名账户 1 个页面，两个账户各 5 个页面。未修改 Demo 应用组件来迎合采集。

本机 `60218` 已选择并加载该成功批次的原始 manifest、截图及成功报告；负向测试失败报告保留在测试目录。真实浏览器确认全部 11 张图片加载成功，Sign in 分组仅一个节点。README 截图为此产物的实际画布。
