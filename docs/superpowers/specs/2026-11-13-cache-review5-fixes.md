# 跨认证入口共享依赖修复

沿用审查中 ESM 与 CommonJS 两个跨入口复现，按 systematic-debugging 修复入口级登记与 Node 进程级依赖缓存不一致的根因。保留现有未提交修改。

## 实现

- fingerprintModule 返回仅供内部使用的逐文件依赖摘要，并按真实文件路径解析模块身份及相对导入，避免路径别名绕过登记。
- 认证加载器按依赖真实路径维护已加载摘要，跨入口也检查共享文件。共享 ESM 未变化允许继续使用；任何已登记共享依赖变化要求重启服务。
- 不完整图可能加载可见图之外的文件，因此采用进程级保守边界：加载不完整图后，新的模块认证操作必须重启；已有其他操作加载过模块后，也不允许新操作加载不完整图。更换入口、使用看似独立的入口或重建 runner 不能绕过此边界。同一构建快照内的多页、多账户采集仍可继续。
- 操作身份使用 WeakMap 中的符号 token，不在进程级依赖登记中长期保存包含凭据的快照对象。
- README 同步解释限制。未声称隔离执行任意动态模块。

## 验证

新增真实配置服务 API/Chrome 子进程回归：完整 ESM 图跨入口未变化可通过，修改共享依赖后拒绝新入口；真实路径别名无法绕过。CommonJS 隐藏策略变化后拒绝第二入口，也拒绝后续看似独立的模块入口。反向从已有完整图切换到不完整图同样拒绝。

长期服务测试按真实进程生命周期隔离，避免测试进程预先加载的模块影响新服务的起始条件；没有清空生产登记或禁用原有断言。
