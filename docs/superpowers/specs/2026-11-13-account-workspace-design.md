# Atlas 应用版本与账户工作空间重构设计

状态：用户已确认方案 B，并明确授权制定实施计划、重构及真实验收；不提交、推送或发布。
日期：2026-11-13。

## 1. 意图与已确认决策

Atlas 的目的，是理解一个账户可访问的完整应用路由。任何时刻只有一个账户的工作空间，移除 All accounts，All features 只作用于当前账户。每账户每实际路由只有一个节点，页面内错误、空态和数据变化不产生导航。

用户已选择：输入未变默认复用上次成功地图，保留原采集时间；通过 `atlas build --force` 重新采集。采用 B：稳定应用索引、独立账户工作空间、共享采集资源。先设计审查、用户确认，再计划和实施。

这不是应用运行时快照恢复：Atlas 不冻结数据库、服务器、时间或登录状态。缓存表示过去成功采集的证据；即使输入相同，远端数据仍可能变化。

## 2. 约束与非目标

沿用 React Flow、shadcn/ui 和 Lucide；仅桌面 Viewer。Atlas 连接已运行 Web 地址，不执行 Flutter 构建或启动命令，不导入接入方业务。Demo 保持普通可复制 Flutter 工程。所有私有配置、凭据、指纹和产物在 .atlas/，不得 stage/commit/tag 接入方文件。

保留既有脏工作区。本次明确授权调整页面卡片内容和连接外观；其他公共组件契约不变。对外文案、README、Demo、可复用 skill 英文，内部设计中文。不自动提交、推送、发布。

不做源码路由表解析、不猜测 Flutter 类名、不做运行时数据自动冻结、不做跨机器缓存同步、不做多账户同图、不做自动删除历史资源。本次不承诺所有第三方自定义适配器自动具备安全增量复用。

## 3. 方案比较

A：全账户采集批次，Viewer 严格派生账户图。迁移较小，但缓存和失败边界仍偏全量。
B（用户选定）：应用索引指向账户及视口的成功版本，公共采集资源按依赖复用。支持独立缓存和布局，代价是重构发布协议。
C：每账户完全自包含目录。实现直接，但公共页重复采集，资源及版本一致性更难维护。

## 4. 身份、作用域与存储

- `applicationId`：init 创建的随机 UUID，保存在私有 identity.json。名称、地址、Git HEAD、绝对路径不是身份。旧项目首次新 build 时持锁创建；只查看旧产物不写身份。
- `accountId`：现有账户 UUID；匿名账户保留保留值 @anonymous。改名不改 ID；删除后新建同名账户获得新 UUID。
- `pageId`：保持 accountId + 稳定声明页面 ID；route 是独立唯一性约束，不把名称作为 ID。更改页面声明 ID 等于新页面；route 改变保留 ID，但清除受影响的旧证据。
- `profileId`：标准配置 profile 键（默认保留键），修改尺寸不改身份；改键视为新 profile。
- 工作空间键：applicationId/accountId/profileId。公共匿名节点引用原节点和截图，在不同空间有各自坐标，不能冒充账户截图。
- `revisionId` 是不可变成功版本标识；`captureId` 是真实采集批次标识；`generationId` 是一次原子索引发布标识，三者不得混用。

目标逻辑结构（目录名称可由实施者调整，契约不变）：

```
.atlas/
  identity.json                    # 稳定应用 ID
  atlas.yaml / 现有凭据存储        # 沿用配置入口
  build-state/                    # 私有缓存键、依赖、互斥锁
  generated/
    index.json                    # 唯一原子提交点，schemaVersion=2
    revisions/<revisionId>/        # 不可变账户/profile清单
    captures/<captureId>/          # 真实图片、导航证据、时间
    attempts/<attemptId>.json      # 本次重采失败诊断
```

索引包含应用显示信息、账户列表及每 profile 的当前成功 revision 引用。revision 包含范围内节点/边、引用的 captureId 和原始时间。秘密、认证摘要、源码摘要不写入 Viewer 清单。每个工作空间单独保存布局、镜头、锁定和撤销历史；持久化作用域含应用、账户、profile、布局协议版本，不含 captureId。不同产物来源另加本机 namespace 防止复制目录同时打开时串写。

复制完整 .atlas/ 视作同一应用身份；新应用应重新 init，不能根据相同 URL 自动合并。源码目录移动不重置身份。

## 5. 账户工作空间与公共页面

build 默认协调全部启用账户和所选 profiles；`--profile` 保持现有语义。本次不新增 build --account。Viewer 的账户选择不改变构建范围。

单个账户空间包含自己的全部声明节点，以及通过本账户认证进入/退出边接入的匿名公共页面；沿匿名到匿名边求闭包，但不沿边进入其他具名账户。保留空间内合法边，公共页详情不显示其他账户连接。无认证边的纯公共子图只属于匿名空间，不猜测其所属账户。

存在具名账户时默认恢复最后有效选择，否则选择配置顺序第一启用账户；匿名空间可独立选择查看公共路由。无具名账户时只显示匿名空间。没有任何可采集页面时报告配置错误，不生成空成功地图。

账户改名更新索引显示信息而不重采；节点 role 标签由账户索引解析，历史证据保持原记录。停用/删除账户在下一次成功协调发布中移出当前列表，历史保留。配置变化但尚未 build 时旧地图仍可查看，提示配置已变化，实时会话拒绝不匹配快照。同名账户在选择器辅以短 ID 区分。

切换账户卸载当前画布控制器，取消手势/选中/详情/异步请求，关闭旧实时会话；用 workspace generation 校验迟到结果。共享页的实时打开沿用其匿名采集身份，不能偷偷使用当前账户已登录状态。所有搜索、分组、统计、缩放边界、minimap、布局障碍和关联导航基于空间子图。

真实 Demo 预期：两个具名账户各 6 页、8 条 observed 导航；复用匿名登录页证据，不能复制或伪造账户身份。

## 6. 缓存输入与状态锁

三个概念独立：运行互斥锁防并发写入；成功版本记录决定能否复用；布局锁定仅约束节点移动。

缓存键使用规范化语义输入：采集协议/工具兼容版本、账户 UUID 与认证修订、页面/边/准备/ready 定义、profile 尺寸、baseUrl/routeMode/browser channel、认证和可信适配器实现、源码内容指纹。显示名、Viewer 文案、布局和输出绝对路径不影响采集键。注释和 YAML 键顺序不应造成重采。密码不进入公开摘要；私有认证版本使用本机秘密参与的摘要，变更保守失效。

源码范围：优先明确 sourceFiles（扩展为可声明的项目内文件/目录范围，展开排序）；未指定时默认 Flutter 项目源码及资源/依赖声明：lib/、web/、pubspec.yaml、pubspec.lock 和 pubspec 声明的本地 assets/fonts。项目内 path 依赖也纳入；无法解析或范围外依赖必须显式声明可信指纹或禁用复用并说明原因。现有 sourceFiles 相对于配置目录解析的语义保持不变；新增默认范围相对于应用根解析，doctor 显示规范化后的项目相对路径。目录新增/删除文件都参与摘要。排除 .git/、.atlas/、build/、.dart_tool/、node_modules/；显式声明与排除冲突报错，不静默遗漏。链接不能无界遍历；超出项目根的输入需显式可信适配器指纹。

有 Git：记录 HEAD/dirty 作为私有诊断，实际仍比较范围内内容，包含未跟踪文件；仅 HEAD 改变、相关内容相同不强制重采。无 Git：同样内容算法，不影响功能。源码范围不是对任意应用依赖完整性的自动证明，doctor 输出有效范围与未覆盖项。

配置/凭据改变按账户及依赖失效；源码或全局适配器变化失效所有依赖它的账户。公共截图键不包含其他账户密码，但公共到具名账户导航证据属于具名账户 revision，必须包含该账户认证修订。公共页面证据变更会使引用它的空间依赖更新。仅视口变化失效该 profile。

可选可信适配器提供运行产物版本/数据版本，纳入键；没有该信号时允许用户已选择的输入缓存，但 Viewer 明示 `Reused capture` 和原时间，不显示运行时已验证。未声明完整输入的自定义 adapter/record/discovery 继续真实采集或显式禁用缓存，不以空指纹命中。

命中需同时满足键匹配、成功记录有效、所有引用清单与资源存在且校验值正确。损坏视为缓存未命中并说明原因。纯命中不修改成功时间、captureId、图片或 revision；可在非语义运行日志记录本次检查，不为此制造新成功版本。--force 对所选 profiles 的全部启用账户和依赖公共资源真实重采。

## 7. 发布、失败与并发

单应用构建持全局互斥锁（本次采用串行发布，避免过早引入账户锁协调）；其他 build/config 更新按现有配置序列化机制协调，锁内不重复获取同一输出锁。record/discovery 写入相同存储也必须遵循同一写入协议。

流程：锁 → 读取一致配置快照 → 校验并计算输入 → 计算所有账户/profile依赖与命中 → 暂存需要的采集 → 再验证源码/配置/凭据输入未变 → 写不可变资源和 revision → 原子 rename index.json → 释放锁。

同一 build 命令的所有选中 profiles/账户作为一个可见发布事务。任一必需采集失败，全部保留上一索引；成功暂存资源不变成当前地图，后续不自动作为已发布缓存命中。未选中的 profiles 保留原引用并标示自身时间/配置兼容性。账户列表变化涉及所有 profile；未重建 profile 对已删除账户不再暴露，其剩余旧版本只读且需要时提示需重建。

崩溃前无索引提交则旧版可用；提交后所有引用资源已完整落盘。读者先取得一份索引快照，之后只读不可变引用，不拼接跨 generation 数据。失败报告与当前成功地图分开显示。沿用现有 PID/token 所有权机制，无法证明锁归属时不删除；互斥门异常保留诊断，不自动破坏性恢复。无旧成功地图时失败展示报告而非空成功页。

复用不会绕过实时安全检查。实时打开必须验证对应工作空间当前配置/认证兼容性，并重新登录、ready；源码变化拒绝旧会话。仅其他账户改动不应使当前账户失效，因此从全配置 raw version 改为依赖作用域修订。

## 8. 页面名称与卡片

新增可选 `pageName`（YAML/adapter 明确提供），透传采集协议和 Viewer；不扫描 Dart，不从 URL 或截图推断类名。优先 pageName，否则现有 title；来源在详情标明 Declared page name / Page title。用户声明 LoginPage 即按原文显示，但不额外声称已解析或验证源码类型。Demo 仅在确认真实类名后声明。

卡片：名称主标题、route 次行、截图、现有锁定操作。去掉重复账户/组名、正常 Captured、Default 页脚；组名在筛选和详情，采集状态与时间在详情，异常/待采集需在卡片可见。保留图片比例、选中、拖拽、键盘可达和必要错误信息。长名称/路由省略但可访问完整文本。工作空间头部提供账户/视口上下文，不在每卡重复。

## 9. 连接设计

保留内部定位能力但不显示黑色 Handle，也不提供无意义的手工接线交互。使用开放式箭头 >，沿线方向旋转；状态仍由颜色和虚实线表达，不能仅凭颜色区分。

双向边是两个独立可选、有各自 action/验证状态的有向边。使用独立端点偏移及通道，不能共享同一条反向路径；多重同向动作同样独立。按无向节点对分组，稳定 edge ID 决定并行序号。

一对多采用有限分散：按相对目标位置排序，在卡片可用侧边内分配有最小间距的出口；入边同理，避开标题和角落。不在整卡无限扩散，不把路径合并成难以选择的树。高出入度空间不足时分层通道并保留独立命中区域；允许局部线段相交，不承诺任意图无交叉。

仅改变相关节点邻边的路由；确定性排序避免 hover/选中导致路径跳动。保留障碍避让预算和增量缓存，不恢复曾失败的多账户全局路由试验。hover 高亮不改变显式选中；标签避碰并可在详情查看完整 action。具体端口间距、箭头尺寸和曲线/折线圆角留给实现者依据真实桌面验收调整。

## 10. 安装与依赖诊断

采集由包内 Playwright 库驱动独立 Chrome；浏览器安装与 JS 依赖是两回事。发布包应包含 CLI、capture 模块、预构建 Viewer，并将实际外部 imports 纳入 dependencies；使用者无需 pnpm、Vite、React 构建工具或 Flutter SDK。Node 必须符合打包 engines；默认 Chrome 必须已安装。其他 channel 按配置检查，不自动下载安装浏览器。

新增 `atlas doctor`：检查 Node 支持范围、模块解析、Viewer 资源完整性、配置/身份/输出权限、浏览器可执行与隔离上下文启动关闭、应用 URL 可达、源码覆盖范围。提供结构化结果及英文修复建议，不输出密码。URL 检查只判断可达，不冒充认证成功；认证检查沿用 config 的明确操作。无应用配置时仍可完成安装检查。

build 命中仅需配置、指纹、产物检查，不要求 Chrome或应用在线；doctor 完整诊断可以报告缺失但不阻止离线查看。真实重采前自动执行必需依赖预检，缺 Chrome/模块/不可达立即明确失败；不把缺浏览器误报为页面 ready 超时。检查只创建/清理工具自己的浏览器资源。

## 11. 兼容与迁移

新写入 schemaVersion=2 索引/空间清单；Viewer 继续读取 v1 manifest 并在内存派生单账户空间，v1 不能凭旧 sourceFingerprint直接获得新缓存资格。首次 v2 build 真实采集后建立成功缓存记录。v1 只有 role 无 accountId 时使用限于该旧产物的合成身份并提示无法识别同名真实账户，不宣称恢复 UUID。已有 accountId 则直接使用。

不重写旧截图和 manifest，不删除旧目录。旧全图布局不直接复制到每账户以免保留混合布局；首次空间采用确定性布局，旧布局存储保留。旧公共节点只按真实匿名身份与认证边归属处理，不按名称猜测。

标准 YAML 路径本次完整支持增量缓存；自定义适配器保留现有完整采集入口，经统一产物适配后也只显示单账户空间。record/discovery 不命中新 build 缓存，真实产出必须保存 accountId/route唯一性，不扩展为自动源码发现。

## 12. 验收与交付门槛

后端按项目要求：先生产实现，再单元测试，再集成测试，统一验证、汇总失败、批量修复后回归。此设计阶段不运行实施验收，不以历史绿色结果计数。

- 身份：改名/同名/停用/删除再创建、移动目录、匿名应用、profile变化；不存在跨账户详情、镜头、布局历史和迟到实时结果。
- 缓存：纯命中浏览器启动次数为零，captureId/时间/资源不变；force真实操作；Git clean/dirty/untracked、无 Git、文件新增删除、适配器/依赖/凭据变更、显示名变更、资源损坏均有测试。源码一致但运行数据变更必须仍明确是历史复用。
- 发布：多profile中途失败、并发构建、配置采集中变化、提交前后崩溃、锁所有权、失败保留旧图、公共资源失效传播，验证无混合索引。
- 画布：真实 Chrome 验证单账户 Demo各6页8边、名称/长文本/失败卡片、无可见黑点、开放箭头、双向分离、一对多端点分散、选择和拖拽。100页150边反馈 p95 ≤50ms，记录机器、采样流程、原始结果；不以减少输入规模通过。
- 安装：在仓库外临时目录安装真实 tarball，运行时不得通过 symlink、NODE_PATH 或仓库 node_modules 解析依赖；仅使用声明 engines 支持的实际 Node与预装Chrome。测试产物依赖解析路径，确认 Viewer无需开发工具。
- 独立采集：复制普通 Demo到独立目录，以外部验收 harness 按普通 Flutter命令启动（Atlas不启动）；从安装后的CLI完成 init/config/doctor/build/view、实际登录及导航、复用/force/失败保留。应用fixture不写入通用产品代码。另用通用测试应用覆盖失败和认证边界。
- 缺失场景：Chrome不可用、缺模块/静态资源、Node不受支持、应用停机、认证失效、无Git、缓存可离线查看。无法在宿主移除Chrome时，用隔离可执行路径/测试容器验证缺失分支，报告验证方式，不卸载用户软件。
- 门槛：类型检查、格式检查、受影响Node/组件测试、项目要求的完整回归、真实Chrome浏览器及独立Demo验收全部通过。现有发布包尚未证明干净安装采集闭环，实施后必须补证，不宣称已完成。
