# 单账户路由工作空间：调查记录

本文件记录系统性排查与建议，不是已获批准的实施设计。用户最新明确：工程目的是梳理同一账户的一套完整路由，不展示所有账户的混合画布。

## 结论

缺少的产品边界是「账户工作空间」。Demo 行为与采集关系一致，没有多余登录落点或登出来源。画布把账户做成一张全局图上的筛选条件，布局、交互、详情与统计没有独立的账户作用域。增加分区或调整线条不能补上这一边界。

真实 Demo 的成功产物包含 11 个账户路由节点、16 条 observed 导航。跨账户连接恰好四条：匿名 /login 分别到两个账户的 /home；两个账户的 /me 分别回到同一个匿名 /login。每个具名账户各一个 landing、一个 logout 来源。`demo/lib/pages.dart` 的登录提交与 Profile 操作、`demo/lib/app.dart` 的认证重定向与此一致。

## 各边界的现状

| 边界 | 已确认现状 | 影响 |
| --- | --- | --- |
| 默认入口 | AppMap 的 role 初值为“全部”，提供 All accounts 选项 | 首屏就是混合账户图 |
| 账户身份 | 目录展开与截图携带稳定 accountId，Viewer 以显示名 role 建下拉框和筛选 | 同名账户会被合并显示；名称更改不适合作为工作空间身份 |
| 共享入口 | sharedRoles 是可选显示名配置，默认开发入口未配置；标准 CLI 仅转发 | 选具名账户可能把共享登录页与登录／登出连接隐藏，不能自然形成完整流程 |
| 图与几何 | controller 接收原始全账户 map，只用 visibleIds 标记隐藏 | 隐藏账户仍参与几何障碍、增量协调、边界与布局历史；筛选不是独立画布 |
| 布局存储 | CLI layoutKey 包含输出来源、视口，未包含账户 | 账户之间共用坐标、镜头、锁定、撤销重做和存储通知 |
| 详情与关联跳转 | relations 从全 map.edges 获取；点击关联页执行 setRole('全部') | 从登录页看到其他账户连接；跟随连接会回到全账户图 |
| 数据统计 | 底部采集与 verified 数量统计全 map | 即使过滤到一个账户，统计也不是当前流程的统计 |
| 连线与选择 | hover 直接改变 selectedEdge；选中的页面与边可同时来自不同流程 | 详情上下文混乱；这个问题在单账户模式中也应独立修复 |
| 采集与实时会话 | 采集节点已按 accountId 区分；实时操作按 screenId 对应的私有快照账户打开独立 Chrome | 现有采集与会话基础可以保留，无需为了展示而复制或合并账户身份 |

## 推荐的工作空间契约（待确认）

1. 任意时刻只显示一个账户的完整流程，移除 All accounts。All features 仅表示当前账户的全部功能。
2. 以稳定 accountId 选择账户；显示名只是标签。默认恢复上次有效账户，失效时回退到确定的可用账户。
3. 当前账户图包含本账户页面及与之相连的必要公共未登录页面；公共页面复用原始截图和节点身份，不为每个账户重新伪造采集节点。只保留属于当前账户的登录与登出关系。
4. 在工作空间内派生节点与边，再交给画布控制器；其他账户的节点不以隐藏障碍等形式参与此画布。功能筛选与搜索在这个边界之内进行。
5. 账户独立保存布局、镜头、锁定、撤销重做与布局模式。存储作用域包括项目／产物来源、视口配置、稳定账户 ID。共享登录页在不同账户工作空间可以有各自的位置。
6. 关联导航不能切换账户；切换账户清理当前选页、选边、临时手势与未完成实时会话，防止异步结果回填另一个账户。
7. 页面数、导航数、minimap、缩放边界与详情均只基于当前工作空间。账户改名不丢布局，同名账户不合并。
8. 布局应表达当前账户的登录入口、实际 landing 与登出来源；不按“Sign in”等文案猜测应用语义，也不强制通用应用只能有一个认证分支。Demo 的单 landing／单 logout 来源是本应用的真实行为。

对当前 Demo，按上述“保留公共登录页”的边界，每个账户应展示 6 个页面、8 条已验证导航；切换账户替换整套画布上下文，而不是把 11 个节点一起排版。

## 实现途径比较

- 推荐：保留现有多账户采集批次，在 Viewer 入口派生严格的单账户工作空间，并隔离布局和交互状态。解决展示问题，同时保持截图证据、失败保留与离线查看能力。
- 备选：CLI 按账户拆分独立产物／独立 Viewer。隔离更偏向文件导出，但需要同时调整构建发布、共享页面引用和产物选择；对当前“一个工具中切换账户查看”的目标增加了额外复杂度。
- 不采用：只删除 All accounts 选项或继续给全局图加分区。前者不能隔离布局、关联导航与统计；后者与用户明确的单账户目标相悖。

## 验收范围建议

- 两个、十个账户下，默认图始终只含一个账户；切换后没有前一账户页面、连线、详情或实时会话。
- Demo 每账户 6 页／8 条真实导航，登录只到本账户 /home，登出只从本账户 /me 回公共 /login。
- 不同账户对同一个公共登录页拖动、锁定和调整镜头互不影响；各自撤销重做、刷新恢复有效。
- 账户名称重复或改名不改变身份；删除当前账户、首次没有具名账户、有纯匿名应用均有明确行为。
- All features、功能筛选、搜索、关联导航、覆盖模式、统计和实时打开都不能逃逸当前工作空间。
- 页面内状态去重、真实内容就绪、截图成功不等于连线验证等既有契约保持。
- Chrome 实测功能与性能，保留 100 页面／150 连线反馈 p95 ≤ 50ms 的既有门槛。

## 本轮试验与回退

先前在明确单账户目标前进行的“多账户分区＋独立走线”试验已撤回。试验源代码、失败测试和路径坐标证据归档于 `.runtime/flow-readability/withdrawn-multi-account-trial/`，没有作为最终实现保留。没有改动上一轮路由去重、Demo 账户身份与采集产物。

撤回后 TypeScript 检查通过；10 项既有真实 Chrome 画布验收通过，100 页面／150 连线反馈 p95 37.8ms。单账户工作空间改造尚未实施，不将这些检查称为新设计的验收。
