# 画布紧凑 Header 设计

状态：已实施并通过桌面 Chrome 验收。范围仅为 Viewer 顶部框架，不包含画布卡片或接入流程改造。

## 目标与依据

用户要求把占空间的筛选栏整合进 Header，并将角色平铺按钮改成下拉菜单。1543 × 953 桌面窗口实测：当前 Header 为 48px，工具栏为 60px，共占 108px。目标合并为 56px 的单行 Header，回收 52px 画布高度。

## 方案与取舍

- 采用单行 Header：角色、功能分组、搜索常驻；布局操作进入 Layout 菜单；刷新、适应画布、详情开关为紧凑图标按钮。与用户提出的 Header 和角色下拉方向一致。
- 不采用仅将原工具栏移入 Header 的双行方案：仍然占两行，不能解决空间问题。
- 不采用将全部筛选藏入弹层的方案：角色和搜索属于高频入口，不应增加每次使用的点击数。

## 布局与行为

```text
[品牌] | [All accounts ▾] [All features ▾] [Search…]    [Layout ▾] [刷新] [全景] [详情]
```

- 角色采用原生单选下拉，默认 All accounts，选项使用完整账户名；长名称只在闭合状态省略，值及无障碍名称保持完整。维持现有筛选语义、页面身份与视口行为。
- 功能分组直接复用现有 GroupSelect；发现模式保留 Screen coverage 下拉。搜索始终可见，允许随桌面窗口收缩。
- Layout 弹层完整复用 CanvasToolbar，保留其 Undo、Redo、锁定和整理按钮及整理确认流程，不改内部结构、文字、尺寸或交互。菜单关闭后焦点回到入口；菜单操作不触发画布移动。
- 刷新、全景与详情开关放在 Header 右侧，保留明确的英文 tooltip、无障碍名称和详情展开状态。自定义 Header 链接保留可达入口。
- 可见数量、采集数量与已验证连线数量移至底部状态区，保留信息，减少顶部重复计数。
- 在 1543、1305、1024px 桌面宽度验证。较窄桌面窗口允许品牌标题省略、控件容器收缩；不增加手机断点，不通过压缩卡片换取空间。

## 视觉约定

- 色彩：白色工作栏 `#FFFFFF`、画布底色 `#F2F4F7`、正文 `#263444`、次要信息 `#738091`、边界 `#E3E7ED`、选中与焦点 `#224F6C`。
- 字体：沿用系统界面字体，品牌与操作采用现有字号体系；不引入展示字体或额外字体下载。
- 原则：以画布作为主要工作面；筛选在左、视图操作在右；只用分隔线表示功能分组，不增加装饰性卡片、说明文字或动效。
- 自评：这是开发画布的框架收敛，不是营销页面换肤。保留现有色彩和组件，让角色数量不再决定工具栏长度，以可用画布高度衡量效果。

## 保护边界与验收

- ScreenCard、GroupSelect、CanvasToolbar 的既有内部契约保持不变，不增加 density／variant 或内部 CSS 覆盖；只调整外层组合与 Header 自身控件。
- 下拉、搜索、覆盖范围、布局、刷新、全景及详情开关均保留；键盘操作、菜单焦点和 Esc 行为可验证。
- 长品牌名、长账户名、多账户及发现模式下 Header 仍为单行，不横向撑出桌面窗口。
- 真实 Demo 验证筛选结果和操作有效，截图确认卡片字段、行数、尺寸及默认外观保持一致。
- 实施顺序：确认本短设计后，编写小范围实施计划；完成页面组合与相应测试，再运行类型检查、相关测试和真实 Chrome 验收。
