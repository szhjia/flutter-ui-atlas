# Atlas 本地配置页与多角色自动采集设计

日期：2026-11-11。状态：config 正式接入已实施，提供本机服务、配置与凭据保存、通用表单/MJS 真实登录测试；多角色自动采集与 Viewer 收敛仍待实施。验收证据见《配置页正式接入验证记录》。

正式页面位于 `packages/config-ui/`：左侧角色表格、右侧编辑栏，通过 `ConfigAdapter` 连接本机 HTTP 服务。已选设计图与历史验收记录迁入 docs；独立原型在正式验收后移除。

## 已确认的产品方向

- `atlas config` 启动本地 Web 配置页，设置应用连接、采集角色及用户名／密码。
- 角色包含稳定的 `tag` 和用于显示的 `name`，例如 `admin`／`管理员`。
- `atlas build` 读取已保存配置，自动登录并按角色采集，不在终端新增角色或询问密码。
- `atlas view` 展示图谱、截图和采集证据，移除实时页面、iframe 及相关预览会话能力。
- 首版认证范围为用户名／密码。配置页提供登录结果与诊断，不嵌入应用实时页面。

## 现状与因果边界

设计时 `packages/cli/index.mjs` 尚无 config 子命令；本轮已增加正式入口，后续所述采集链路缺口仍存在。

`packages/capture/declarative.mjs` 每次 `open()` 都创建新浏览器上下文，未传入认证状态；`role` 仅为页面标签，`matchesState()` 只核对路由和可见内容。`DiscoveryAdapter` 同样没有统一的账号输入与认证生命周期接口。`packages/capture/discovery.mjs` 的历史复用条件未单独绑定账号及角色配置。

本轮使用临时通用页面、虚构身份和真实 Chrome 验证：新上下文回到登录页；恢复认证状态后两页截图及一条实际点击关系通过；将预期标签改为另一角色，默认判据仍接受原账号页面。此验证证明浏览器会话与身份判据的缺口，不构成接入方真实账号验收。

因此，需要在声明式采集和 discovery 两条路径共用认证与角色作用域，不能仅给终端加输入框或只修改其中一条采集路径。

## 三个命令的分工

| 命令 | 输入与行为 | 结果 |
| --- | --- | --- |
| `atlas config` | 启动并打开本机配置页；修改设置、管理角色、测试登录 | 保存项目配置与本机凭据 |
| `atlas build` | 自动读取所有启用角色；可用拟议的 `--role admin` 限定单个角色 | 生成图谱与本次尝试报告 |
| `atlas view` | 读取成功产物和报告 | 查看图谱与历史证据 |

首次使用可以直接进入配置页，补齐项目初始化信息。已有配置只补充缺失字段，不重置原目录、适配器或未知配置项。不通过配置页自动重写受信任的 MJS 源码；应用专用逻辑仍由适配器维护。

## 配置页

### 项目设置

- 应用名称、Flutter Web 地址和现有采集配置。
- 登录页地址、用户名字段、密码字段、提交按钮、登录成功及失败判据。
- 共同的路由目录来源和页面就绪判据由项目配置／适配器提供，供全部角色复用。

登录字段映射每个项目配置一次，新增角色不重复设置。标准表单优先使用语义标签定位；定位不唯一或不受支持时给出具体配置提示，不猜测后继续执行。复杂登录流程使用本地适配器的认证接口。

### 角色管理

每个角色提供以下字段：

| 字段 | 约束与用途 |
| --- | --- |
| tag | 唯一、稳定的机器标识，例如 `admin`；初版限定小写字母开头，后续使用小写字母、数字、下划线和连字符 |
| name | 中文显示名称，例如 `管理员`；修改名称不改变节点 ID 或布局 |
| 用户名 | 与该角色绑定的本机登录账号 |
| 密码 | 可保存以支持无人值守登录；列表不回显，编辑时留空表示保持原值，清除使用独立操作 |
| 启用 | 决定普通 `build` 是否采集此角色；仅由角色列表的开关控制，编辑栏不重复展示 |

提供新增、编辑、停用、删除和测试登录。新增角色仅登记采集身份，不创建应用中的账号或服务端权限。删除前明确影响范围；停用不清除历史图谱。已有产物的删除另行处理，不与删除账号配置隐式绑定。

测试登录显示未配置、未测试、验证中、通过或失败及可行动原因。用户名、密码、应用地址或登录方式变化后，旧测试结果失效；`build` 仍需重新确认真实会话，不能把配置页的历史测试通过当成本次证据。

`tag/name` 是用户命名。应用提供角色／身份检查能力时核验实际账号与权限；只有登录成功证据时，明确记录角色名称为用户声明，不把名称当作权限证明。

## 配置与凭据保存

- 可共享的应用配置及角色 `tag/name/enabled` 存入 `.atlas/atlas.yaml`，不包含真实用户名或密码。
- 初版建议把账号和密码保存到接入方本机 `.atlas/local/credentials.json`，认证状态也放在该本机目录；目录权限 0700、文件权限 0600，写入采用原子替换。此方案是本机受限文件存储，不宣称磁盘内容已加密。
- 保存前维护 `.atlas/.gitignore` 中的 `/local/` 排除规则；若目标凭据文件已被 Git 跟踪，拒绝写入并提示处理，不能认为新增忽略规则会取消跟踪。
- 配置页用简短文案说明凭据仅用于本机自动登录。凭据读取／写入封装为接口，后续可替换为系统凭据库，不让该扩展影响角色和采集协议。
- 配置读取接口只返回密码是否已设置，不返回已有密码。密码不得进入 URL、日志、错误报告、manifest、截图标签、Viewer 配置或打包产物。
- 工具仓库仅使用虚构账号的通用示例；接入方的真实凭据不进入本仓库。

这样保存的是自动化所需的本机凭据，不能再沿用“只保存会话、失效后在 build 提示输入密码”的交互。

## 自动构建链路

1. 读取本次配置快照，选择全部启用角色；如指定角色，则校验该 tag 存在且配置完整。
2. 在启动采集前校验登录适配、凭据引用和共同路由目录。未配置、无启用角色或缺密码时，给出 `atlas config` 指引并以非零退出码结束，不等待终端输入。
3. 为每个角色建立独立认证会话。先检查可复用会话；失效时自动用已保存凭据登录。错误密码明确失败，不无界重试。
4. 核验实际身份、入口及登录成功条件。一个账号有多个可切换角色时，由应用适配器执行选择与核验，不能复制会话后改个标签。
5. 同一角色登录一次，后续页面及流程复用其认证状态。优先保留活会话；需要独立上下文时通过统一会话工厂恢复认证，不能假设所有认证都能用默认 storageState 完整复制。
6. 按共同目录访问页面、等待真实内容就绪并截图；按登记的真实操作或 journeys 验证导航关系。实际账号在采集中变化或会话失效时，停止该角色采集并记录原因。
7. 每个角色形成独立成功／失败结果，最后原子发布汇总图谱和报告。任一必选角色失败，命令非零退出；仍可保留其他角色本次成功结果及失败角色上次成功结果，但必须标明各自批次、时间和本轮失败，不能宣称全部更新成功。

初版按角色顺序运行，避免同账号并发互相干扰。浏览器隔离不代表服务端数据隔离；执行范围仍以已登记的页面与操作为准。

新增角色后，配置页保存即可。下次普通 `build` 自动包含该角色；希望只补新角色时可以指定 `--role <tag>`。未选角色保留原采集时间，不标记为本轮重新验证。

## 图谱身份与覆盖含义

- 共同路由目录定义候选页面；新增角色不要求复制 screens/edges 或为每个页面重复填写角色字段。
- 采集状态键至少包括项目、角色 tag、稳定页面状态 ID；动态详情使用样本 ID 区分，避免同路由的不同身份或状态互相覆盖。
- 修改显示 name 不改变状态键；修改账号绑定、应用环境或登录适配版本时使认证缓存失效，旧证据不能静默复用为本次结果。
- 默认重新采集选中角色的页面和流程。仅源码指纹相同不足以证明真实账号的数据和权限未变化。
- 结果区分已到达、明确权限拒绝、缺少样本、尚未验证和采集失败。超时不等于无权限，未访问不等于不存在。
- 路由层级、声明跳转和实际观察导航关系保留不同证据含义；截图不能提升连线为 observed。
- 无共同目录时只能报告已观察范围，不能显示“路由已全部覆盖”。动态参数样本及不能直接进入的页面仍由适配器／journeys 提供。

角色、会话、尝试报告与图谱身份的协议应先定义，再实现 CLI、采集器和界面。新产物协议需明确版本策略及旧 v1 图谱读取路径，不能让旧读者把不同角色误合并。

## 配置服务与 Viewer 边界

配置服务是独立的本机写入服务，只监听回环地址、使用严格的 Host／Origin 校验和会话令牌保护写入，限制请求体大小。配置仅允许写入已解析项目的受控路径。服务退出后配置页明确断开，终端可打印入口作为自动打开浏览器失败时的回退。

Viewer 继续只读产物，不暴露凭据接口。移除实时页签、iframe、预览 URL 与预览会话隔离配置；更新接入文档和对应测试，保留截图、关系、角色筛选、采集时间和失败原因。既有页面卡片的内部结构、字段、布局与样式保持原契约。

## 实现与验收范围

按项目约定先完成协议及生产实现，再补单元与集成测试，最后集中验证与批量修复。此文档不作为实现或验收已完成的证明。

- 配置读写：tag 重复、名称变更、停用角色、密码保持／清除、未知配置保留、原子写失败、已跟踪凭据拒绝写入。
- 登录失败路径：错误密码、服务不可达、登录判据不符、身份不符、会话失效；所有错误输出不泄露凭据。
- 多角色独立示例：两个用户名／密码身份，同一路由内容不同；自动 build 确认隔离、正确截图与真实操作连线。
- 非交互构建：无 TTY 可运行，缺配置立即失败，不出现终端提问。
- 汇总发布：一个角色失败时保留可辨认的旧证据；其他角色结果和本轮失败报告不丢失，进程退出码反映失败。
- 真实桌面 Chrome：在配置页新增、编辑、测试、启用角色；关闭配置服务后独立运行 build；停止 Flutter 后仍可在 Viewer 查看图谱。
- 服务边界：跨源写入拒绝、敏感文件不可被 Viewer 获取、配置读取不返回密码、并发保存与构建使用明确配置快照。
- 打包验收：全局安装包包含配置页及服务；在独立 Flutter 工程运行 config/build/view，不依赖源码仓库的 node_modules 或业务 fixture。

首版已确认使用受限本机凭据文件，并支持通用表单＋MJS 认证扩展。本轮只交付 config；多角色 build、路由适配及 Viewer 收敛按后续计划实施。
