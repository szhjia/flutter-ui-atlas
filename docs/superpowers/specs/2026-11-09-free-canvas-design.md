# Flutter UI Atlas 自由画布设计

日期：2026-11-09。状态：用户于2026-11-09确认完整设计，已进入实施计划阶段；本文不代表功能已实现。

## 1. 意图与已确认范围

让开发者在一张稳定、可自由编排的画布中查看真实 Flutter 页面与导航关系。页面位置应反映人的工作思路，阅读和拖动时不能因为自动布局而失去方向。

用户已确认：拖动时周围页面局部避让，锁定的页面不动，不触发全图重排；先把画布做好，组件详情后续细化。用户也同意在设计文档后查看独立、可操作的示意。示意仅帮助评审，不能替代正式实现或验收。

本轮包含：页面间距、自由布局、局部避让、锁定、撤销、位置保存、连线绕障与标签显示、筛选与缩放。保留当前截图详情和真实 Web 预览。

不包含：Flutter 组件树、组件命名与色彩检查器、截图取色、采集调度/RPC、新业务页面、截图内容或公共产品组件重设计、多人协作、跨设备同步、手工创建业务导航关系。组件元数据未来应来自 Flutter 适配器，不从截图猜测。

## 2. 当前问题与方案选择

当前 `packages/viewer/src/AppMap.tsx` 使用固定 6 列、横向步长 280、纵向步长 570；卡片宽 224，因此横向空隙仅 56。位置只保存在组件状态中，筛选会按当前数组顺序重新放置未拖动节点。连线为 smoothstep，标签跟随各条 SVG 边的绘制顺序，可能被后画的边覆盖。

考虑的方向：

| 方向 | 优点 | 代价/适用边界 |
| --- | --- | --- |
| 扩大规则网格 | 实现简单、对齐清楚 | 仍是固定排版，不满足自由组织与局部避让 |
| 持续力导向或每次全图重新布局 | 自动形成关系网络 | 一次操作可能移动远处页面，破坏用户记忆，不符合用户要求 |
| 自由位置＋有限局部避让 | 保留手工布局，附近节点让位，锁定可作为锚点 | 需要明确冲突、撤销与保存规则 |

采用第三种，这是用户已选定的方向。以下参数与技术细节为设计建议，可在批准时调整。

## 3. 视觉与操作结构

画布占主要空间；工具栏紧凑，不增加营销式说明。无选中页时侧栏可收起；选中节点后显示现有截图/实时预览及入站、出站关系。保持现有蓝灰工具风格，视觉重点给页面截图。

建议基础颜色：画布 `#F2F4F7`，面板/标签 `#FFFFFF`，主要文字 `#263444`，选择/焦点 `#356D91`，已验证连线 `#287D78`，失败/冲突 `#B75B48`。未验证关系用虚线和文字，锁定用锁图标与文字，不只靠颜色区分。

沿用系统中文无衬线字体；工具文字 12–13px，节点标题 14px，侧栏标题 18px。路由标识可使用现有等宽字体，普通状态不强行等宽。所有标题、面板内容左对齐。

工具栏：身份/分组/搜索｜关系显示（全部/选中页）｜撤销/重做｜适应视图。选中节点的工具栏提供锁定/解锁。布局菜单提供“整理未锁定页面”，与“适应视图”明确区分；适应视图只改变镜头。

节点保持真实截图原貌，不修改截图内组件。使用布局包围盒测量卡片实际宽高，不能假定所有屏幕都是手机或所有标题只有一行。

建议初始水平间距 160、垂直间距 120（画布坐标单位）；交互时最小安全间距为水平 96、垂直 80。拖动不强制吸附网格，可显示对齐参考线；首版不实现多选拖动。

## 4. 初次布局、刷新与过滤

首次打开无保存布局的应用时，按入口和导航关系生成一次疏松布局：先聚合循环，再按可达层次从左到右放置；同层页面纵向错开，分支保留空白。断开的子图独立成组，保留至少 240 的组间距。布局目标是生成可用起点，不追求完全没有交叉线。

该计算仅发生在首次布局或用户主动“整理未锁定页面”时。后者需明确提示影响范围，并作为一次可撤销操作。整理仅作用于当前可见且未锁定的节点，操作前显示影响数量；隐藏节点与锁定节点均作为固定障碍，坐标不变。撤销恢复此次被整理的全部节点。无法在限定计算预算内完成整理时保留原布局并提示原因。

刷新采集结果：稳定 screen.id 保留坐标与锁定；截图更新不改变节点位置。新增节点放在已知相邻页面的空闲区域，无相邻关系的放入独立“新增页面”区域；绝不推动已存在节点。删除节点从当前画布消失，其布局记录暂留，重新出现可恢复。恢复位置已被占用时，为未锁定恢复节点寻找最近空位；已锁定恢复节点有冲突则保留原坐标和锁定记录，暂不绘制该节点，在侧栏待定位列表提示冲突；由用户选择解锁后重新定位，或先移开占位者再恢复。待定位列表不是画布上的新位置，不得自动修改锁定坐标。

筛选只隐藏节点与相关连线，不重新排布，不改锁定和已保存坐标，不自动改变镜头。隐藏节点仍作为固定障碍；靠近它们拖动时显示淡色占位框及“此处有隐藏页面”，避免推走用户看不到的内容。清除筛选后恢复原位。无结果时展示清除筛选操作。

图片或标题使节点包围盒变化时重新测量。若造成冲突，不在后台推走其他节点；显示冲突提示，交给下一次局部拖动或显式整理处理。首版优先让画布卡片外壳尺寸在同一 viewport 配置内稳定。

## 5. 拖动、局部避让与锁定

### 5.1 正常拖动

按下未锁定节点时保存本次手势开始的完整位置快照。被拖动页紧跟指针；避让结果基于该快照和当前指针重新计算，不能累加每一帧推挤量，避免抖动和位置漂移。

以被拖动节点的目标包围盒及安全间距寻找碰撞邻居，只让实际受碰撞影响的未锁定邻居移动。优先沿拖动方向让位；多个方向可行时选择总位移最小的方案，平局按稳定节点 ID 决定。由邻居引起的碰撞允许有限传播。

局部边界：最多影响 12 个邻居，且所有被推动节点的起始中心需处于目标节点中心两个最大节点对角线范围内。这些是可调常量，不是 UI 选项。越界不能偷偷扩大为全局重排。

拖动期间展示候选位置及邻居的让位预览。松手时把本页及所有受影响邻居一次性提交，形成一条历史记录。Esc 取消整个手势并恢复全部受影响节点；撤销也恢复整个操作，而不只恢复被拖动页。

### 5.2 锁定和无解

锁定节点不可被拖动、自动推挤或整理移动；仍可选中、查看截图、操作实时预览及解锁。标题旁显示固定锁图标，键盘操作有名称和状态。

目标撞上锁定或隐藏节点时，先在局部范围内寻找最近合法停放点并展示候选轮廓；不能让节点在不可落点处停留。无法解决、碰撞传播超出预算或迭代不收敛时，显示红色候选框与“空间不足，请换个位置或解锁邻近页面”。松手回到手势起点，不保留任何邻居的临时位移，不自动扩大画布节点间距或重排整图。

键盘移动走同一碰撞求解与提交路径；单次方向键为一个可撤销操作，可按短连续按键合并。焦点不进入 iframe 时才处理画布快捷键，输入框中的撤销不能被画布截获。

### 5.3 保存与历史

位置、锁定、视口只在手势提交或明确操作后保存；不保存拖动中间帧。支持撤销/重做拖动、锁定和显式整理，首版内存历史上限 50 条；刷新后恢复布局但不恢复撤销栈。

宿主通过 `AtlasViewerAdapter.layoutKey` 提供稳定、独立的应用/采集配置标识，例如应用 ID 加 viewport 配置；不得使用 captureId 或仅用 URL。身份与分组共用一个布局。保存结构包含 schemaVersion、screenId→{x,y,locked}、viewport；localStorage 按 layoutKey 隔离。更换 viewport 配置使用不同 key，避免手机和平板卡片尺寸互相污染。

同一 key 多标签页采用最后一次已完成操作写入；非活动标签页收到 storage 事件后提示“布局已在其他窗口更新”，提供载入按钮，不打断正在拖动的页面。首版不合并并发编辑。

缺少 layoutKey 时仍可使用画布，但不跨会话保存，并明确提示。存储不可用、配额不足、JSON 损坏或版本不支持时保留当前内存操作，并显示“布局未保存”；不能静默清空或覆盖未知版本数据。删除所有布局/跨设备同步不在本轮范围。

## 6. 连线与标题

### 6.1 绘制层级

由下至上：背景 → 关系线段/箭头 → 页面节点 → 独立 HTML 标签层 → 选中态与操作控件。标签为不透明浅底、细边框、内边距，不依赖 SVG 元素追加顺序；普通连线永远不能穿过标签文字。

“置顶”不意味着盖住页面：标签位置同样参与碰撞检测，不得覆盖节点包围盒。标签点击选中关系，详情展示完整动作、来源、目标与验证状态。

### 6.2 路径与障碍

以节点测量包围盒外扩 16 为障碍，使用四向折线路由，拐角做小圆角。端口可从上/下/左/右选取，选择使路径代价最小且方向稳定的一组；源、目标仅允许在各自端口出口处穿过自己的外扩范围。中间路径不得穿过其他页面。

路径代价包括长度、转弯、与已有边的重叠和相对上一条路径的变化；拖动时优先保留原有走向，避免每帧左右跳变。只重新计算移动节点关联的边，以及旧路径与受影响节点新旧位置相交的边；远处关系不全量跳动。

同向并行边分配不同出入口与通道；相反方向边分开走线；自环走节点外侧。允许必要的线段交叉，不承诺任意图都能完全无交叉。选中关系时提升其线段、箭头和标签的对比度，其他关系淡化。

路由搜索有时间/候选数上限；找不到合法通路时不画穿页的假路径，改为在端口显示关系计数及“路径暂无法展开”，该关系仍可在详情列表访问。不能因路由失败而改变已有导航验证状态。

### 6.3 标签密度

优先把标题放在较长的水平线段上。候选位置依次避开页面、其他已放置标签及高优先级端口。选中/悬停关系的标签优先；普通标签冲突无法解决时收为动作计数标记，点击或悬停可看完整文字。

缩放 < 0.45 时默认隐藏普通动作标题，保留节点和关系走向；选中/悬停关系仍显示标签，字号不小于 11 个屏幕像素。放大后恢复标签。长标题最多两行，超出用省略，详情始终完整，不因标签密度削减关系数据。

## 7. 技术组织与性能边界

继续使用当前 React Flow 画布，不更换宿主框架。通用实现放在独立 Atlas 工程，寓科只注入 layoutKey；不得把角色、路由、业务组件名称写进工具。

建议拆分：纯几何碰撞求解器、初次/显式布局器、边路由器、标签排布器、布局存储适配层、画布交互协调层。求解器输入/输出均为不可变位置快照，便于验证局部性、锁定和确定性。具体搜索算法和是否使用 Worker 留给实施计划决定；只有实测主线程阻塞才引入额外复杂度。

拖动预览最多每动画帧提交一次，指针事件先合并；邻居反馈短过渡，移动中的主节点不使用追赶动画。用户选择减少动态效果时取消让位动画。松手时进行完整合法性检查，预览与提交共用约束。

验收数据规模：当前真实 56 页，以及 100 节点/150 边的合成密集图。参考设备上记录拖动反馈耗时，目标 p95 ≤ 50ms；若预算耗尽则保持上个合法候选并提示，不冻结 UI，也不降低锁定/不重叠约束。

## 8. 验收案例

| 场景 | 必须满足 |
| --- | --- |
| 节点拖入一小簇页面 | 簇内必要邻居让位，远处节点坐标完全不变，松手无重叠 |
| 簇中存在锁定页面 | 锁定页坐标不变；不能解开时回退整个手势 |
| 超过局部预算/密集无解 | 明确提示，不全图重排、不留半次推挤 |
| 拖动后 Esc / 撤销 / 重做 | 被拖页与被推动邻居一起恢复/重做 |
| 搜索隐藏邻居后拖动 | 隐藏节点作为固定障碍，清除筛选后没有重叠 |
| 刷新采集/浏览器刷新 | 同 ID 坐标与锁定保留；新增页不挪动已有页 |
| 失败采集 | 不改变画布布局，也不覆盖上一批可用截图；失败报告仍可追溯 |
| 连线从其他页面附近经过 | 线段不穿页面，所有可见标题不被线段遮挡 |
| 并行边/反向边/自环/长标题 | 方向明确，标签可读，必要收起时详情可完整访问 |
| 0.2 / 0.65 / 1.0 缩放 | 标签密度随尺度变化，选中标签仍可读 |
| 存储异常/多窗口修改 | 如实提示，不丢失当前内存操作、不抢走正在拖动的控制权 |
| 1100 / 1600 宽度与键盘 | 工具可用、焦点可见、输入框和 iframe 不被快捷键干扰 |

实施验证需要：几何单元测试（固定、边界、不重叠、确定性）、布局存储测试、真实浏览器拖动/撤销/筛选/标签遮挡检查；原生 App 与业务组件未修改，不扩展到无关后端或原生全量回归。
