# 认证依赖解析关系与符号链接边界修复

## 根因与本轮范围

前几轮直接触发条件不同，但主要属于同一个问题簇：静态输入指纹、Node 模块解析及进程缓存的模型没有完整对齐。此前围绕单个复现补回归，未充分覆盖相邻维度的组合，导致同类遗漏逐轮出现。本轮按 systematic-debugging 将路径身份和解析关系统一纳入检查，并明确覆盖矩阵；测试通过不代表穷尽任意 JavaScript 行为。

依赖登记现在同时包含文件内容和“请求路径 → 真实目标”。指纹也包含解析关系，因此文件集合及内容不变、只交换链接目标仍会失效。依赖路径中任意层级的符号链接都使图不完整；同入口、跨入口或同一操作作用域中，已登记解析目标变化均拒绝继续使用旧认证模块。

配置目录先规范化为稳定真实路径，保留其内部模块声明的链接关系，区分 macOS `/var` 系统路径别名与应用声明的链接。普通无链接 fixture 使用真实目录；符号链接用例显式创建链接，不靠宿主路径的偶然结构。

## 已覆盖矩阵

| 维度 | 用例与边界 |
| --- | --- |
| 导入语法 | 普通/带注释导入、转导出、URL 编码、字面量动态导入、不确定动态导入 |
| 模块格式 | 完整 ESM、间接 CommonJS、createRequire 别名、不确定 `.js` 格式 |
| 路径身份 | 文件链接、依赖父目录链接、入口父目录链接、真实路径别名 |
| 变化内容 | 文件内容改变、目标改指向、文件集合和内容相同但交换解析目标 |
| 使用关系 | 同入口、跨入口、同构建作用域、不同操作、长期服务重测、新 CLI 进程 |
| 正向兼容 | 未变化的共享 ESM 可继续使用，多页/多账户构建正常，认证超时释放资源 |
| 缓存发布 | 命中保留时间、force、损坏记录恢复、构建并发锁、报告/索引写失败、发布前源码变化保留旧图 |

新增五条 Chrome 路径：同入口、跨入口、同作用域、文件链接、入口父目录改指向。通过真实配置服务 HTTP API或真实采集适配器完成首次认证，改变链接后验证拒绝，不以静态断言替代浏览器路径。另有纯输入测试证明交换目标时即使文件内容摘要集合相同，图摘要仍变化。
