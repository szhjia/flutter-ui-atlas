## 用户标注 1：仅保留列表开关

用户明确要求移除编辑栏里重复的「参与自动采集」，并验证保存角色不会覆盖列表状态。本节覆盖原设计图中的重复开关，属于用户指定的设计变更。

- 已删除编辑栏的启停行及专用样式。浏览器实际读取：编辑栏 switch 数量为 0，角色表格 switch 数量为 3。登录测试区域自然上移，其余表单与列表布局保持原结构。
- 在独立预览页复现了一个并发问题：将审核员从停用切到启用后立即保存名称，保存结束开关又变回 false。根因是角色编辑草稿仍携带旧的 enabled，`saveRole` 把该旧值写回角色。
- 修正字段归属：从 `RoleDraft` 和草稿构造中移除 enabled；`saveRole` 只改编辑字段并保留已有角色最新的启停值，启停仅由 `setEnabled` 修改。列表操作不再重写编辑草稿，也不会影响未保存的名称等内容。
- 修正后在真实浏览器重复同一路径：列表启用后立即保存，最终 aria-checked 为 true；再次打开编辑栏，列表停用后立即保存，最终为 false。两次保存都保留了名称修改。测试完成后恢复示例名称和停用状态。
- 回归测试 `tests/role-state.test.ts` 共 7 项全部通过：启用／停用后的已有草稿保存、两种并发调用顺序、新角色默认启用后在列表停用。
- 本轮 `npm run type-check`、`npm test`、`npm run build` 和 `git diff --check` 均通过。验证页 error/warn 日志为空。
- 修改前后均使用用户当前 1305 × 1154 视口，截图输出同尺寸，不做密度缩放。证据为 `../.runtime/config-ui/comment-1-before.png`、`comment-1-after.png`；同屏对比为 `comment-1-comparison.png`。已查看对比，确认只移除了重复区域及其占位，无新增 P0/P1/P2 视觉问题。

本节验证范围仍为交互模板及内存适配器，不表示真实登录或 CLI 构建链路已接通。
