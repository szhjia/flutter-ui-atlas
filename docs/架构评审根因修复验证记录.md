## 明确的运行边界

- `.atlas-lock-guard` 只在锁元数据变更时短暂持有，不在整个采集或录制期间持有。竞争最多等 1 秒。门内崩溃时拒绝继续写入，错误给出绝对路径；确认相关写入任务均已停止后人工清理。不能自动强删残留门，否则会重现同类竞争。
- 成功的 release 幂等，并发 release 共享执行中 Promise；失败不缓存，门恢复后可重试。高层采集若在释放阶段失败，应按错误中的路径恢复现场，确认无写入任务后清理残留，不能忽略错误继续并行写入。
- 同来源适配器应保持实例稳定；换源提供新实例。回环放行策略、manifest schema 与公共卡片契约保持原有规则。
- 本次未扩展 CI、依赖扫描语法或安装级打包验收；这些属于前次评估中记下的后续工程能力，不是本次已确认故障。
