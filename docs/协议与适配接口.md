# Flutter UI Atlas 协议 v1

本版交付进程内适配协议和 JSON 采集文件协议。浏览器由采集端控制，画布读取结果；未实现远程 RPC，不把设计中的 postMessage 通道当作已提供能力。

## CLI 开发边界

Atlas CLI 不执行 Flutter 命令，不构建、不启动接入方应用；通过读取 pubspec 识别工程，不要求安装 Flutter SDK。全局 CLI 的 `build` 连接已运行的 Flutter Web，`view` 提供预编译 Viewer。`capture` 是 `build` 的兼容命令。带 `--url` 的入口采集只在回环开发地址上执行，确认实际入口和可见的就绪文字后才写入截图。只提供地址时保存候选节点。路由目录和已验证导航仍由配置及浏览器证据提供。

在 Flutter 根目录运行 `atlas init`，生成 `.atlas/atlas.yaml`、本机接入说明，并在 Flutter 工程根 `.gitignore` 中维护 `/.atlas/`，整个目录（含配置、凭据、私有快照和产物）不提交。保留已有忽略内容和换行，不重复追加相同规则；拒绝符号链接、非普通忽略文件与 `.atlas` 内已有 Git 跟踪文件，不修改 Git 索引。重复 init 不覆盖 YAML。显式 `--config` 优先，否则依次检查工程的 `.atlas/atlas.yaml`、根目录旧 JSON/MJS 配置和仓库的 `tools/app-atlas`。旧工具配置中的 `flutterProject` 相对配置文件所在目录。初始化会引用能识别到的旧 MJS 适配器，也可用 `--adapter-config` 显式指定受信任的适配器。初始化时可沿用适配器已配置的 `.atlas` 一级产物子目录。

YAML 中 `title` 是工程显示名，`baseUrl` 是已运行的 Flutter Web 地址，`port` 是独立 Viewer 的端口。未登记 `screens` 时采集单个本地入口，`readyText` 指定入口的可见就绪文字，留空时只登记候选。配置 `screens` 和 `edges` 时沿用声明式采集接口，`sourceFiles` 路径以 YAML 所在目录为准。需要录制或复杂场景时，`adapterConfig` 可引用本地 MJS 配置。YAML 可设置共用字段，如 `port`、`output` 和 `viewport`，而浏览器入口、就绪条件和源码指纹由适配器提供。MJS 的 `output` 不会被继承。

通过工程 `.atlas/atlas.yaml` 运行时，默认写入同级 `generated/`，`output` 可指定 `.atlas` 内的子目录。无配置的快捷模式同样使用 `.atlas/generated/`。显式使用旧 JSON/MJS 配置时继续采用旧路径规则。

## 本机配置服务（config v1）

`atlas config [--config <工程/.atlas/atlas.yaml>] [--port <0..65535>] [--no-open]` 从 Flutter 根目录或子目录打开配置页。端口默认由系统分配，自动打开 Google Chrome 失败时保留终端入口。首次保存创建官方 YAML；旧 JSON/MJS 不被自动改写，已有 MJS 继续由 `adapterConfig` 引用。直接旧配置先迁入 YAML，避免改变原路径语义。

YAML 保留未知字段和注释，增加 `roles: [{id,tag,name,enabled}]` 与 `authentication`。角色 ID 是稳定 UUID；名称修改不改变 ID。用户名、密码与登录测试记录只保存在 `.atlas/local/credentials.json`（版本 1），目录 0700、文件 0600；这是受限明文文件，不宣称磁盘加密。工程根 `.gitignore` 排除整个 `/.atlas/`；内部 `.atlas/.gitignore` 可以向后兼容保留，但不能替代根忽略规则。已有 Git 跟踪、失效忽略规则或符号链接私有路径拒绝写入，不自动取消跟踪。

写入按项目串行，凭据与 YAML 使用原子替换及事务日志；未提交的事务在下次访问时回滚，提交标记已落盘的事务仅清理日志。损坏文件拒绝覆盖。读取不返回密码，只返回 `passwordSet`。角色编辑请求携带 revision，列表启停独立合并；旧编辑版本冲突返回 409。删除角色同时移除凭据，保留已有图谱。

`authentication` 支持 `{type: 'none'}`、`{type: 'module', module: '../tools/auth.mjs'}` 或以下通用表单（路径相对 YAML 所在目录；通用表单登录页必须与 baseUrl 同源）：

```yaml
authentication:
  type: form
  loginUrl: http://127.0.0.1:8080/
  username: {kind: label, name: 登录账号}
  password: {kind: label, name: 登录密码}
  submit: {kind: role, role: button, name: 登录}
  success: {kind: text, name: 登录成功}
  failure: {kind: text, name: 账号或密码错误}
```

定位方式为精确 label、role/name 或 text，目标须唯一。失败判据可省略。`allowRemoteUrls: true` 显式放行远程应用地址；配置服务本身始终只监听回环地址。

可信 MJS 模块默认导出 `AuthenticationAdapter`，类型在 `packages/cli/config-contract.ts`：`version` 为非空版本，`login({page, role: {tag}, credentials: {username,password}, baseUrl})` 执行登录；`verify({page, role})` 返回实时 `{authenticated, identityMatches?}`。身份不匹配不得通过。适配器或其依赖行为变化时应更新版本及模块源码；模块不通过网页上传。

每次测试创建独立 Chrome 上下文，15 秒超时，结束释放。返回的 `checkId` 在本服务内有效 5 分钟，与凭据及认证配置绑定；保存时只采用匹配结果。失败与成功均可保存；用户名、密码、角色 tag、应用地址或登录配置改变后旧结果失效。配置测试不是图谱或权限覆盖证据。

HTTP API 仅供本机页面：GET `/api/config`、`/api/health`，POST `/api/project`、`/api/role`、`/api/enabled`、`/api/delete-role`、`/api/test-login`。所有 API 要求入口 fragment 中的会话令牌放入 `X-Atlas-Token`，写请求还需同源 Origin；Host 必须等于实际监听地址。JSON 请求最多 64 KiB，不提供任意文件访问或跨域接口。服务退出页面断开并保留草稿。Viewer 不提供这些接口。

配置页账户由标准 CLI 构建与工具实时会话消费，保持 v1 图谱兼容。登录测试只证明该次认证通过；完整图谱仍需各页面与操作的就绪、路由、身份和实际正文证据。

## 数据与证据（采集产物）

- `schemaVersion=1`，不兼容变更升级主版本；读者拒绝未知版本。
- 每份目录属于一个应用；每个账户的同一实际路由只允许一个节点。`screens[].id` 是该路由页面的稳定 ID；多账户展开后仍使用账户 UUID 与 YAML 页面 ID 的组合。`accountId` 保存稳定账户身份，缺省的兼容适配器以 role 为账户作用域。空态、错误提示、加购或同路由参数状态不新增页面 ID，`state` 仅描述代表性截图，不参与页面身份。
- `role/group/state` 是应用提供的显示标签；通用库不解释身份或业务权限。
- `entry/route` 由应用适配器解释，工具不执行目录里的任意脚本。
- `edges` 引用存在的页面 ID。`declared` 只是声明；`observed` 必须由实际操作、就绪判定与目标路由匹配共同产生；失败写 `failed/reason`。截图成功不能提升连线等级。
- `captureId/capturedAt/sourceFingerprint/viewport/scenarioId/seedVersion` 共同描述本次采集条件。磁盘源码指纹不是浏览器加载的构建版本证明。
- `runtimeErrors` 保留运行错误，失败页面不展示成功截图。缺少源码指纹时，manifest 以空字符串记录，画布显示未核验。
- 每个批次归档 `attempt.json`，必要时附带该批 manifest；根目录 `latest-attempt.json` 记录状态、失败原因和报告地址。先写报告和最近尝试，再切换当前 manifest。发布遇到写入错误时保留当前地图并归档失败，最近尝试路径不可写时可从命令输出找到批次报告。

## 失败语义

统一约定：读取「上一个好状态」失败时，若会话内已有好状态则保留它并叠加可行动诊断（Viewer 内置文案默认英文，保留适配器返回的原始原因首行与下一步动作：重试、恢复入口或报告地址）；只有从未有过好状态才进入错误态。诊断信息不静默丢失。

- Viewer 加载与刷新：仅同一来源读取 manifest 失败时保留上一次成功结果；首次加载或切换来源后失败显示错误屏与重新加载按钮。配置来源由有序 `artifactPaths` 与 `layoutKey` 标识；适配器来源由实例引用、`loadManifest` 函数引用与 `layoutKey` 标识，宿主应保持同来源适配器实例稳定，切换来源时提供新实例。切换来源即隔离旧快照、详情与布局，不能把旧图套入新来源的预览配置。
- 独立画布入口（`#atlas-config`）配置解析失败时渲染英文错误提示与重新加载，不白屏；空标签沿用默认配置。
- 画布布局存储损坏（有数据但不可读或未通过校验）时：会话继续以自动整理布局工作，保存暂停且不覆盖原数据，画布提供「丢弃损坏布局」恢复出口；浏览器存储本身不可用不属于损坏，不提供该出口。载入外部布局、保留本地布局与保存时均同步损坏状态；丢弃后重新保存的失败诊断必须保留。
- 采集与自动发现批次失败时，批内归档保留已收集节点的最终状态，`attempt.json` 的 `failedScreens`/`failedEdges` 为真实统计：自动发现失败批次按「未能确认」计数（非 `captured` 页面、非 `observed` 连线）；声明式采集与自动发现成功批次只统计显式 `failed`（`pending` 候选不算失败）。

## 输出目录写入互斥

同一 output 目录同一时刻至多一个写入任务：声明式采集（`capture`）与自动发现（`runDiscovery`）共用锁目录 `.atlas-lock`。

- 获取锁后在锁目录写 `meta.json`（`pid` 与获取时间），整个批次（创建批次目录到发布完成）持锁，结束时释放；手动录制会话持锁数分钟属预期。
- 所有锁目录的获取、接管与释放均先取得 `.atlas-lock-guard` 互斥门（原子 mkdir），在短临界区内完成检查和修改，再释放互斥门；整个采集批次只持有 `.atlas-lock`。互斥门竞争最多等待 1 秒，其余活锁立即拒绝。
- 遇到已存在的批次锁：持有进程已退出或缺失持有信息超过 60 秒时，打告警后在互斥门内接管；不强抢存活持有者。持有信息增加唯一 `token`，释放必须同时匹配 PID 与 token，不能删除同进程后来取得的新锁或身份不明的锁。
- 拒绝信息包含锁绝对路径与（可读时的）持有 PID：`采集输出目录正被另一个写入任务使用（锁：<路径>，持有进程 PID <pid>）。若该任务已退出，删除该锁目录后重试。`
- 已知边界：持有 PID 被操作系统回收给无关进程时，锁会被误判为存活，只能按指引手工清理。若进程在锁修改临界区内崩溃，互斥门可能残留：工具不自动删除互斥门，避免再次引入检查与删除竞争；错误提供互斥门绝对路径，确认相关写入任务均已停止后手工删除再重试。跨设备或网络文件系统不在保证范围内。
- 旧版本 `.atlas-discovery-lock` 残留不被读取，可手工删除。

## 接口

`packages/capture/adapter.ts` 是浏览器适配入口：

1. `catalog()`：应用维护目录或从自己的路由表派生目录；有参数页面提供确定样本。
2. `sourceFingerprint()`：可选，定义本项目真实源码范围。
3. `open({browser,screen,viewport})`：建立独立上下文并返回会话，失败必须清理已创建上下文。
4. 会话的 `ready(screen)` 等待内容就绪。`currentRoute()` 读取实际规范路由，`matchesState(screen)` 根据当前内容或会话证据即时判断状态，不能直接回显预期 ID 或上次就绪结果。采集器在截图前后核对路由和状态。
5. `perform(session,edge)` 执行真实点击或输入；声明式 `edges.steps` 按顺序执行真实操作。省略或连线设置 `verify: false` 时保持 declared。同账户同路由的原地操作不是导航，不得声明为页面连线。跨账户身份切换可以使用相同 URL；目标身份在操作前已成立时保持 declared，操作后源身份仍成立则 failed。
6. `close()`：无论成功失败均释放会话。

`AtlasViewerAdapter` 注入结果加载，选填 `loadLatestAttempt()`、`previewUrl()`、源码指纹和品牌信息。`isolatedPreview: true` 表示宿主确实按预览会话 ID 隔离了应用数据。URL 必须由可信适配器生成。

## CLI 本地配置

`atlas capture --config` 和 `atlas view --config` 读取同一配置。相对文件路径以配置所在目录为基准。共有字段为 `output`（默认 `.atlas/generated`）、`publicPath`（默认 `/generated`）、`viewport`（默认 393×852）、`port`（预览默认 60200）、可选 `title` 和 `layoutKey`。

- JSON 配置提供 `baseUrl`、`routeMode`（`hash` 或 `pathname`）与 `screens`。每页提供 `id`、`title`、以 `/` 开头的 `route` 和 `ready`（`{role, name}` 或 `{text}`，精确匹配可见内容）。可选 `entry` 指定与基址同源的入口 URL 和查询参数，`role/group/state` 为显示标签。默认采集等待入口、路由和内容同时就绪。hash 模式核对入口路径，忽略 fragment 内查询参数，空 fragment 等价于 `/`；同一账户同一路由的重复声明会被拒绝；可见正文用于就绪验证，不作为另建页面的依据。
- `routePrefix`（可选，如 `/app`）仅在 `pathname` 模式生效：实际路径为 `routePrefix + route`，`route` 字段登记构造后的完整路径，匹配天然对称；hash 模式忽略该字段但值仍会校验（以 `/` 开头且不以 `/` 结尾、不含点段、反斜杠与控制字符，含编码形态）。pathname 的最终 URL 规范化后也必须位于前缀目录内，不能通过页面 route 的点段逃离部署目录。
- 回环边界：yaml/json 数据配置的 `baseUrl`（含 entryMode 单入口形态）与 `preview.origin` 默认只允许回环地址（`127.0.0.1`、`localhost`、`[::1]`），与 `--url` 约束一致。确需访问局域网或远程开发服务时，设置 `allowRemoteUrls: true`（布尔值）显式放行，拒绝与放行文案都指明该字段。`.mjs` 适配器及其 `previewUrls` 属可信本地代码，不受回环限制；`.mjs` 配置中的 `viewer.preview.origin` 属数据字段，同样受回环约束。
- 浏览器通道：CLI 启动浏览器默认使用 `chrome` 通道。配置字段 `browserChannel`（字符串）可改用其他通道（如 `chromium`、`msedge`、`chrome-beta`），环境变量 `ATLAS_BROWSER_CHANNEL` 优先于配置；两者为空或非字符串（含 null）时给出中文报错，通过校验的值去除首尾空白。程序化注入 browser 实例的调用方不受影响。
- `edges` 可提供 `id/source/target/action` 和 `click: {role, name}`。点击目标须唯一。默认浏览器操作超时 15000ms，可用 `timeoutMs` 覆盖。可选 `sourceFiles` 按列出的本地文件计算源码指纹。
- 本地 `.mjs` 配置默认导出含 `adapter` 的对象。自定义预览可提供 `previewUrls`，键为页面 ID。配置作为本地代码加载，仅使用可信文件。应用服务启动、演示数据准备和预览会话隔离由接入方负责。
- 需要所有登记连线均通过实际操作的项目可设置 `requireObservedEdges: true`。若连线因缺少可区分证据保留为 `declared`，批次失败，报告保留原判定原因。
- `view` 独立读取产物及预览设置。采集目录或就绪判据校验失败后，使用原配置仍可查看旧图和报告。JSON 模式的实时入口取自最近一次成功采集。

## 声明式多账户与命名视口（本轮契约）

配置页维护 `roles: [{id,tag,name,enabled}]` 与凭据；YAML 描述采集目录，不复制密码。账户 ID 为稳定 UUID，页面模板 ID 为稳定字符串，展开后页面 ID 为 `<账户 UUID>:<页面模板 ID>`。匿名身份使用保留 Tag `@anonymous`。名称或 Tag 修改不得改变账户 UUID；页面显示名变化不得改变模板 ID。

- `profiles` 是命名视口映射，如 `phone: {width: 393, height: 852}`、`pad: {width: 1024, height: 768}`。名称为字母开头的字母、数字、下划线或短横线组合；宽高为正整数。未选 profile 时使用全部配置；旧 `viewport` 单视口保持兼容，各 profile 独立输出与布局。
- `screens[].roles` 是不重复的非空账户 Tag 数组，`@anonymous` 表示未登录页面。省略时使用启用账户；没有账户时使用匿名身份。停用账户不参与新采集，未配置 Tag 明确报错。具名账户需要完整凭据和认证方式。
- 页面 `route` 沿用最终入口 URL 的规范值：hash 模式读取 fragment 中的路由，pathname 模式读取完整路径，中文、空格与已有百分号编码按 URL 规则处理，与采集和实时会话的实际路由一致。
- `screens[].prepare` 是到达目标状态前的有序操作，例如进入商城、选择商品、加购。准备通过浏览器真实交互完成，不向普通应用注入账户、购物车或内部状态。
- `screens[].ready.all` 表示全部判据同时成立；`ready.any` 允许完整判据分支的任意一个成立，例如同一路由的合法空态或有数据内容。标题、身份、商品和合计等仍须验证，不能靠拆成多个状态节点代替路由建模。旧 `{text}` 与 `{role,name}` 判据保持兼容；`{not: 条件}` 要求子判据不成立，可区分正常登录与同路由错误提示。不能仅凭 URL 或页面存在就认为已就绪。
- 定位器支持配置页的 `{kind: label|role|text, name, role?}`，兼容 `{role,name}`、`{text}`。`{any: [定位器, ...]}` 合并 phone／pad 的不同语义角色；操作时仍须恰有一个可见目标，多个匹配会失败。
- `edges[].steps` 是连线的有序真实操作，步骤包含 `action` 和定位 `target`；旧 `click` 保持兼容。连线仍需操作后目标路由及状态成立才能成为 observed。缺少操作的声明关系保持 declared。匿名源页到具名账户目标页的边先使用目标账户的认证器真实登录，再执行 steps；登录边可声明 `steps: []`，无需把有效密码写入流程文件。
- 连线按同账户或一端匿名的身份组合展开，展开后 ID 为 `<源账户 UUID>:<目标账户 UUID>:<连线模板 ID>`，匿名端使用 `@anonymous`。不同端点组合拥有不同 ID；账户名称、Tag 或角色声明顺序变化不改变同一组合的 ID。
- 文本模板仅可引用 `{{role.id}}`、`{{role.tag}}`、`{{role.name}}`、`{{role.username}}`；不支持密码模板。模板展开与角色选择在服务端完成，私有凭据不进入公开 Viewer 配置或公开产物。

示意片段（账户通过配置页设置）：

```yaml
profiles:
  phone: {width: 393, height: 852}
  pad: {width: 1024, height: 768}
screens:
  - id: home
    title: 首页
    route: /home
    roles: [user1, user2]
    prepare: []
    ready:
      all:
        - {text: 首页}
        - {text: '当前账户 {{role.username}}'}
  - id: shop
    title: 商城
    route: /shop
    roles: [user1, user2]
    ready: {text: 商城}
edges:
  - id: open-shop
    source: home
    target: shop
    action: 打开商城
    steps:
      - action: click
        target: {role: button, name: 商城}
```

### 私有构建快照

配置服务向采集运行时提供 `readBuildSnapshot()`，包含固定的配置、稳定账户 UUID、当时的启用状态及服务端凭据。公开配置读取接口仍不返回密码。`assertCurrent()` 校验配置或凭据是否变化；变化后明确拒绝把旧快照用于新任务，已有成功图谱保留。后续配置保存不修改已读取的快照对象。

每个工具窗口在 `.atlas/local/sessions/<captureId>-<会话UUID>.json` 保存私有运行信息（文件0600、目录0700），含当前页面、视口、自有进程 PID 与本机 CDP 调试端点；关闭即删除所属记录。端点授予本机会话控制权，不注入网页或 manifest，也不提供 HTTP 下载入口。公开 manifest、静态 Viewer 配置、错误消息不得暴露密码。启动实时会话必须绑定成功批次的 captureId、稳定 screenId、配置版本和源码指纹，不能把当前配置套到旧截图。

## 工具管理的实时 Chrome 会话（本轮契约）

实时操作使用工具新建的独立 Chrome 上下文，依据对应私有快照登录、执行页面准备并验证就绪。应用仍是普通应用，无需 Atlas SDK、专用入口、`atlasSession` 或场景查询参数。会话隔离浏览器存储，不会清空或接管用户日常 Chrome 会话；应用服务器端数据不因此自动隔离。

服务端会话管理器负责 idle／opening／ready／failed 状态，替换会话先释放旧资源，取消打开请求后回收迟到资源；旧请求不能覆盖或关闭新会话。用户手动关闭 Chrome 页、关闭 Viewer 服务或取消任务都需释放所属资源。失败只报告真实状态，不展示为已就绪。

Viewer 实时 API 为 `/__atlas/live/open`、`/close`、`/status`，由实际提供实时能力的 Viewer 服务注入入口与会话令牌。请求要求 `X-Atlas-Token`，写操作要求同源 Origin，Host 限本机服务；仅接受页面、采集与会话标识，不能由网页传入 URL、凭据或任意代码。工具能力可用时优先提供外部 Chrome 操作；未配置时保留旧预览能力，不能只因前端按钮出现就宣称 CLI 已接通。

旧 `previewUrls`、`preview.origin/sessionParam` 和 `isolatedPreview` 属可选 iframe 兼容契约。只有旧宿主真正实现会话隔离时才能声明 `isolatedPreview: true`；新工具会话不依赖此应用侧机制。

## Flutter 可选注入

`packages/flutter_ui_atlas` 的公开面只有 `AtlasNavigatorObserver`：监听命名 Navigator 路由（push/pop/replace 上报当前命名路由；未命名路由与 remove 不上报——不能据此推断当前页）。Router/IndexedStack 使用自身状态流映射，不能假设 observer 能发现所有标签页。规划中的 `AtlasNavigationAdapter`、`AtlasScenarioProvider`、`AtlasReadinessProbe` 契约草案存于 `lib/src/navigation.dart`（未导出，2026-11-11 评审 P2-5 收缩），待第一个真实接入方验证后重新导出。

需要该可选能力的旧接入可在独立开发入口导入 SDK、组装依赖，正式 `main.dart` 不导入。普通工程及当前 Demo 不要求提供独立入口。库不提供原生插件，也不要求修改 iOS/Android 宿主。自动采集第一版可直接使用浏览器适配器，无须改产品源码；需要精确就绪和逻辑页面事件时再使用 Flutter 接口。

## 边界

不能自动发现所有任意 Dart 分支、登录条件和动态数据；新增页面至少需要目录样本与就绪条件。Web 结果不能替代原生系统页面或原生布局验收。当前未提供增量依赖分析、go_router 专用插件、热重载自动采集与远程运行控制。

## 画布布局适配接口

`AtlasViewerAdapter.layoutKey?: string` 是应用提供的稳定布局命名空间。同一应用不同截图 viewport 使用不同 key；不同采集批次复用同 key。省略时不访问持久化存储，页面可继续拖动和撤销。

存储键：`flutter-ui-atlas:layout:v1:<layoutKey>`。文档包含 `schemaVersion:1`、按稳定页面 ID 保存的 `{x,y,locked}` 和 `{x,y,zoom}` 镜头，以及可选的 `catalogIds`／`pendingIds`（记录上一目录与待定位页面，参与历史恢复）；撤销历史仅在当前会话内保留最多50次。已删除页面的布局记录保留以便恢复。测量尺寸和 React Flow 实例不序列化。

刷新采集通过稳定 ID 合并，不能用 captureId 重挂载画布。正在进行的拖动先取消，再合并新目录。新增页面寻找附近空位；锁定页面回归但旧位置已被占用时进入待定位列表，需手动解锁定位。

布局事件由通用协调器统一处理；宿主不导入局部求解器，也不需要修改 Flutter UI、原生宿主或生产依赖。本文档约束本机布局，不构成跨设备或云端同步协议。

旧布局缺少这两个可选数组时仍可读取；首次载入记录当前目录。升级前没有记录的删除／回归历史无法追溯，旧版工具也不理解待定位字段。

## 自动发现配置

可信本地 `.mjs` 可以提供 `discovery`，使用与手工采集分开的 `output`。接口在 `packages/capture/adapter.ts`。

- `candidates()` 从项目路由定义和演示场景返回稳定页面 ID。只有带 `direct: true` 的候选由 `capture` 直接访问。
- `open()` 返回隔离浏览器会话。 `observe()` 通过实际入口、路由、身份和可见内容返回已就绪页面，证据不足返回空值。 `acceptsUrl()` 限定录制范围。
- `journeys()` 使用调用方提供的浏览器和 `watch(session)`。通过 `step(操作名, 执行真实操作)` 记录测试操作，测试仍自行执行原有断言。无操作的页面切换可通过 `refresh()` 补截图。
- 结果增加 `pending` 页面及可选 `discoverySource`、`recordingSources`。直接访问、动作不明和重叠操作不产生已验证边。同一操作重复录制合并来源。
- 连续批次只有源码指纹、视口、主题、场景和种子版本相同时复用截图与关系。指纹无法确认时每批独立。失败保留当前成功 manifest。
- 配置 `preview.origin` 后，独立 Viewer 只读取该来源的页面相对 `previewPath`。如应用支持按查询参数隔离会话，可配置 `preview.sessionParam`，每次打开时写入新的会话 ID。

## 声明式 Viewer 外壳

- CLI 的可选 `viewer` 可配置 `shell`、`sharedRoles`、`captureHint` 和 `preview`。`shell.title` 是页眉应用名，`shell.logoUrl` 是由浏览器加载的 Logo 图片地址，支持本站根路径或不含凭据的 HTTP(S) 地址。图片未配置、地址无效或加载失败时显示 `shell.logoText`，默认显示 `A`。旧配置仍可传入 `subtitle`，单行页眉省略副标题。
- Viewer 模板默认使用英文，包括工具栏、卡片状态、详情、空态、错误、布局诊断及无障碍标签；入口声明 `lang="en"`，时间采用英文格式。应用提供的页面名、账户名、状态、主题及诊断原样展示。默认采集元数据使用英文；现有图谱协议、页面身份、布局存储与筛选内部标识不变。
- `shell.introNote` 支持纯文本。`shell.headerLinks` 接受 `[{label, href}]`，链接使用本站根路径或不含凭据的 HTTP(S) 地址。加载、失败与正常显示共用页眉。
- React 宿主可以传 `<AppMap config={config}/>`。`AtlasViewerConfig` 增加按优先级排列的同源 `artifactPaths`、可选的 `fingerprintUrl` 和稳定的 `layoutKey`。CLI 从既有 `publicPath`、指纹接口和布局键组装这些值。宿主导航与认证由宿主负责。`<AppMap adapter={adapter}/>` 仍可用。包出口为 `.`（AppMap 与公开类型）、`./model`（manifest 类型）与 `./config`（`createPreviewUrl`/`safeLink`/`readViewerSnapshot`/`readSourceFingerprint` 与 `ViewerSnapshot` 类型），契约测试锚定每个出口指向真实文件。
- Atlas 在目录明确缺失（404 或静态预览的 HTML 回退）时才尝试下一目录，遇到响应错误或无效 manifest 显示错误。报告从本次选中目录读取。所有目录均缺失时，显示优先目录的最近尝试。
- `preview` 声明 `origin`、可选 `sessionParam`、默认查询参数 `query` 和入口白名单 `entries`。白名单按 manifest 的 `entry` 指定 `{path, hashRoute?}`。已有 `previewPath` 必须匹配白名单路径。旧记录缺少预览路径时，`hashRoute: true` 从路由生成 hash。每次打开由 Atlas 生成新的会话 ID，由项目演示服务按该参数隔离数据。旧 CLI 的 `discovery.preview`、`previewUrls` 和 `routeMode` 继续可用。

CLI 配置示例。将图片地址替换为实际可访问的资源。React 宿主将相同的 `shell` 对象放入 `AtlasViewerConfig`。

```yaml
viewer:
  shell:
    title: 示例应用
    logoUrl: https://example.com/brand.png
    logoText: 示
```

## 路由身份修正（2026-11-13）

声明式目录、简单 JSON 适配器、通用采集、发现模式和 Viewer 共享账户＋路由唯一性约束。声明重复或导航自环会在启动浏览器前拒绝；发现模式将新状态 ID 归到已知路由节点，同路由原地动作不记导航。旧重复发现产物不继续合并，旧重复页面产物不会作为正常地图展示，需修正目录后重新采集。只删除 Viewer 中的一张卡片不算修复。

## 应用与账户版本（v2）

标准构建增加 applicationId、profileId、accountId、revisionId 与独立账户空间。generated/index.json 为唯一发布提交点；不可变 revision 引用 captures 下的真实截图及原始采集时间。私有 build-state 保存 HMAC 输入键和资源校验值，不作为 Viewer 静态资源公开。v1 manifest 继续只读兼容，但不能直接命中新缓存。

页面新增可选 pageName，由声明或可信适配器提供并透传；title 保持兼容。账户空间由账户自己的节点与通过认证边相连的匿名节点闭包构成，不沿公共节点进入其他具名账户。截图成功仍不等于连线 observed。

缓存命中不产生新 captureId，不重写 capturedAt。force 才强制重采；全部所选工作空间成功后原子切换索引。运行锁、成功版本记录和画布布局锁是不同状态。
