# Flutter UI Atlas 协议 v1

本版交付进程内适配协议和 JSON 采集文件协议。浏览器由采集端控制，画布读取结果；未实现远程 RPC，不把设计中的 postMessage 通道当作已提供能力。

## 数据与证据

- `schemaVersion=1`，不兼容变更升级主版本；读者拒绝未知版本。
- `screens[].id` 标识一个可重现页面状态。不同身份、空数据、详情参数使用不同 ID，不能只用路由当作状态 ID。
- `role/group/state` 是应用提供的显示标签；通用库不解释身份或业务权限。
- `entry/route` 由应用适配器解释，工具不执行目录里的任意脚本。
- `edges` 引用存在的页面 ID。`declared` 只是声明；`observed` 必须由实际操作、就绪判定与目标路由匹配共同产生；失败写 `failed/reason`。截图成功不能提升连线等级。
- `captureId/capturedAt/sourceFingerprint/viewport/scenarioId/seedVersion` 共同描述本次采集条件。磁盘源码指纹不是浏览器加载的构建版本证明。
- `runtimeErrors` 保留运行错误，失败页面不展示成功截图。缺少源码指纹时，manifest 以空字符串记录，画布显示未核验。
- 每个批次归档 `attempt.json`，必要时附带该批 manifest；根目录 `latest-attempt.json` 记录状态、失败原因和报告地址。先写报告和最近尝试，再切换当前 manifest。发布遇到写入错误时保留当前地图并归档失败，最近尝试路径不可写时可从命令输出找到批次报告。

## 接口

`packages/capture/adapter.ts` 是浏览器适配入口：

1. `catalog()`：应用维护目录或从自己的路由表派生目录；有参数页面提供确定样本。
2. `sourceFingerprint()`：可选，定义本项目真实源码范围。
3. `open({browser,screen,viewport})`：建立独立上下文并返回会话，失败必须清理已创建上下文。
4. 会话的 `ready(screen)` 等待内容就绪。`currentRoute()` 读取实际规范路由，`matchesState(screen)` 根据当前内容或会话证据即时判断状态，不能直接回显预期 ID 或上次就绪结果。采集器在截图前后核对路由和状态。
5. `perform(session,edge)` 执行真实点击或输入。省略或连线设置 `verify: false` 时保持 declared。对于同路由切换，目标状态在操作前已成立时保留 declared 并记录原因，操作后源状态仍成立则标记 failed。
6. `close()`：无论成功失败均释放会话。

`AtlasViewerAdapter` 注入结果加载，选填 `loadLatestAttempt()`、`previewUrl()`、源码指纹和品牌信息。`isolatedPreview: true` 表示宿主确实按预览会话 ID 隔离了应用数据。URL 必须由可信适配器生成。

## CLI 本地配置

`atlas capture --config` 和 `atlas view --config` 读取同一配置。相对文件路径以配置所在目录为基准。共有字段为 `output`（默认 `.atlas/generated`）、`publicPath`（默认 `/generated`）、`viewport`（默认 393×852）、`port`（预览默认 60200）、可选 `title` 和 `layoutKey`。

- JSON 配置提供 `baseUrl`、`routeMode`（`hash` 或 `pathname`）与 `screens`。每页提供 `id`、`title`、以 `/` 开头的 `route` 和 `ready`（`{role, name}` 或 `{text}`，精确匹配可见内容）。可选 `entry` 指定与基址同源的入口 URL 和查询参数，`role/group/state` 为显示标签。默认采集等待入口、路由和内容同时就绪。hash 模式核对入口路径，忽略 fragment 内查询参数，空 fragment 等价于 `/`；用可见内容区分同入口同路由的样本。
- `edges` 可提供 `id/source/target/action` 和 `click: {role, name}`。点击目标须唯一。默认浏览器操作超时 15000ms，可用 `timeoutMs` 覆盖。可选 `sourceFiles` 按列出的本地文件计算源码指纹。
- 本地 `.mjs` 配置默认导出含 `adapter` 的对象。自定义预览可提供 `previewUrls`，键为页面 ID。配置作为本地代码加载，仅使用可信文件。应用服务启动、演示数据准备和预览会话隔离由接入方负责。
- 需要所有登记连线均通过实际操作的项目可设置 `requireObservedEdges: true`。若连线因缺少可区分证据保留为 `declared`，批次失败，报告保留原判定原因。
- `view` 独立读取产物及预览设置。采集目录或就绪判据校验失败后，使用原配置仍可查看旧图和报告。JSON 模式的实时入口取自最近一次成功采集。

## Flutter 可选注入

`packages/flutter_ui_atlas` 提供 `AtlasNavigationAdapter`、`AtlasScenarioProvider`、`AtlasReadinessProbe` 和 `AtlasNavigatorObserver`。Navigator 路由可用 observer；Router/IndexedStack 使用自身状态流映射，不能假设 observer 能发现所有标签页。

在独立开发入口导入 SDK、组装依赖，正式 `main.dart` 不导入。库不提供原生插件，也不要求修改 iOS/Android 宿主。自动采集第一版可直接使用浏览器适配器，无须改产品源码；需要精确就绪和逻辑页面事件时再使用 Flutter 接口。

## 边界

不能自动发现所有任意 Dart 分支、登录条件和动态数据；新增页面至少需要目录样本与就绪条件。Web 结果不能替代原生系统页面或原生布局验收。当前未提供增量依赖分析、go_router 专用插件、热重载自动采集与远程运行控制。

## 画布布局适配接口

`AtlasViewerAdapter.layoutKey?: string` 是应用提供的稳定布局命名空间。同一应用不同截图 viewport 使用不同 key；不同采集批次复用同 key。省略时不访问持久化存储，页面可继续拖动和撤销。

存储键：`flutter-ui-atlas:layout:v1:<layoutKey>`。文档包含 `schemaVersion:1`、按稳定页面 ID 保存的 `{x,y,locked}` 和 `{x,y,zoom}` 镜头，以及可选的 `catalogIds`／`pendingIds`（记录上一目录与待定位页面，参与历史恢复）；撤销历史仅在当前会话内保留最多50次。已删除页面的布局记录保留以便恢复。测量尺寸和 React Flow 实例不序列化。

刷新采集通过稳定 ID 合并，不能用 captureId 重挂载画布。正在进行的拖动先取消，再合并新目录。新增页面寻找附近空位；锁定页面回归但旧位置已被占用时进入待定位列表，需手动解锁定位。

布局事件由通用协调器统一处理；宿主不导入局部求解器，也不需要修改 Flutter UI、原生宿主或生产依赖。本文档约束本机布局，不构成跨设备或云端同步协议。

旧布局缺少这两个可选数组时仍可读取；首次载入记录当前目录。升级前没有记录的删除／回归历史无法追溯，旧版工具也不理解待定位字段。

## 自动发现配置

可信本地 `.mjs` 可以提供 `discovery`，使用与手工采集分开的 `output`。接口在 `packages/capture/adapter.ts`。

- `candidates()` 从项目路由定义和演示场景返回稳定页面 ID。只有带 `direct: true` 的候选由 `capture` 直接访问。
- `open()` 返回隔离浏览器会话。 `observe()` 通过实际入口、路由、身份和可见内容返回已就绪页面，证据不足返回空值。 `acceptsUrl()` 限定录制范围。
- `journeys()` 使用调用方提供的浏览器和 `watch(session)`。通过 `step(操作名, 执行真实操作)` 记录测试操作，测试仍自行执行原有断言。无操作的页面切换可通过 `refresh()` 补截图。
- 结果增加 `pending` 页面及可选 `discoverySource`、`recordingSources`。直接访问、动作不明和重叠操作不产生已验证边。同一操作重复录制合并来源。
- 连续批次只有源码指纹、视口、主题、场景和种子版本相同时复用截图与关系。指纹无法确认时每批独立。失败保留当前成功 manifest。
- 配置 `preview.origin` 后，独立 Viewer 只读取该来源的页面相对 `previewPath`。如应用支持按查询参数隔离会话，可配置 `preview.sessionParam`，每次打开时写入新的会话 ID。

## 声明式 Viewer 外壳

- CLI 的可选 `viewer` 可配置 `shell`、`sharedRoles`、`captureHint` 和 `preview`。`shell` 接受纯文本 `title`、`logoText`、`subtitle`、`introNote`，以及 `headerLinks: [{label, href}]`。链接使用本站根路径或不含凭据的 HTTP(S) 地址。加载、失败与正常显示共用页眉。
- React 宿主可以传 `<AppMap config={config}/>`。`AtlasViewerConfig` 增加按优先级排列的同源 `artifactPaths`、可选的 `fingerprintUrl` 和稳定的 `layoutKey`。CLI 从既有 `publicPath`、指纹接口和布局键组装这些值。宿主导航与认证由宿主负责。`<AppMap adapter={adapter}/>` 仍可用。
- Atlas 在目录明确缺失（404 或静态预览的 HTML 回退）时才尝试下一目录，遇到响应错误或无效 manifest 显示错误。报告从本次选中目录读取。所有目录均缺失时，显示优先目录的最近尝试。
- `preview` 声明 `origin`、可选 `sessionParam`、默认查询参数 `query` 和入口白名单 `entries`。白名单按 manifest 的 `entry` 指定 `{path, hashRoute?}`。已有 `previewPath` 必须匹配白名单路径。旧记录缺少预览路径时，`hashRoute: true` 从路由生成 hash。每次打开由 Atlas 生成新的会话 ID，由项目演示服务按该参数隔离数据。旧 CLI 的 `discovery.preview`、`previewUrls` 和 `routeMode` 继续可用。
